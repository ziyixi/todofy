# iPhone 与多设备

电脑和手机连接同一个 Recall。每次独立安装都有自己的设备 ID、访问记录和待上传队列；云端统一搜索，
Dropbox 统一归档。手机不需要连接 Dropbox，也不用复制电脑的扩展目录或本地数据库。

## 手机安装

1. 在 [GitHub Releases](https://github.com/ziyixi/todofy/releases) 下载当前版本的
   `recall-orion-v<version>.zip`，保存到“文件 → 我的 iPhone”。不要选 Chrome 的 `recall-extension` 包。
2. Orion → `…` → 设置，允许 Chrome 扩展；再进入 `…` → 扩展 → `+` → 从文件安装，选择该 ZIP。
3. 在手机打开 Recall → 设置 → 插件口令，填写 `iPhone`，点“添加口令”，复制。
   打开 Orion 的 Recall 扩展设置，粘贴口令，设备名称沿用现有名称（例如 `iPhone · Orion`），保存。服务器地址已经填好。
   保存只确认本机设置已写入，上传结果在下方单独显示。手机包固定使用手机模式，不依赖浏览器标识。
   超过十二秒未收到回执会显示“保存尚未确认”，并保留输入的口令；不要重新生成口令。

口令只显示一次，不要发到聊天。电脑原有口令继续可用。手机丢失或不再使用时，停用这条独立口令即可，
不影响其他口令或已上传的记录。独立口令是上传凭据，名称便于辨认；同一口令若被复制到多个设备，
停用时这些设备都会停止上传。

已安装的设备名称会保留；如果旧版曾默认显示 `Chrome`，改成 `iPhone` 再保存即可。

手机换版按实际可用的“从文件加载”操作：先停用旧版但不卸载，再加载新 ZIP 并启用新版。
以设置底部的版本号确认使用的是新包。不能假定 Orion 会覆盖旧实例、保留设备 ID 或继承设置。
若新实例没有口令，可复用自己保留的原口令；没有保留时，在 Recall 新增一个手机设备口令，
不要重置其他设备正在使用的共享口令。旧版仍有待上传记录时继续保留；停用扩展不删除云端历史。
ZIP 文件名包含版本号，正式包内的扩展显示名仍是 recall。

## 验收状态

手机曾在一次前台测试自动上传正文、JPEG 和结束访问，之后同版又报告采集停滞。修复后的手机持续使用尚未验收；
短时成功、空心跳、WebKit 检查和 Mac Orion 都不能替代这项验收。详细边界见[验证记录](verification.md#phone-evidence)。
Owner 已暂停手机验收，当前构建工作不要求重装或重新启动观察。

## 手机采集诊断

在 Orion 版扩展设置的“手机采集诊断”卡片：

1. 点“开始诊断”，自动打开固定的公开测试页。
2. 保持测试页前台约一分钟，回到扩展设置点“发送诊断”。本轮不要点“立即上传”，以便核对自动上传。
3. 看到“已发送”后，在聊天里告知即可，无需复制日志。

诊断只观察这一轮，五分钟后停止。发送的是阶段、返回值类型、计数、可见性和固定错误码；
不含网址、标题、正文、图片、原生异常文本或口令。正常采集如果成功，公开测试页本身仍会照常记录。
发送使用已有机器接口，但业务条目为空；它独立于采集队列和普通上传，不消费已有待上传记录。
发送时保留尚未过期的固定错误码，不把既有错误清成正常。发送失败时结果保留在本机，可以再次点“发送诊断”。测试页没有打开也可以发送已有结果。

Recall 网站“设置”会出现最近一份“采集诊断”回执，供 agent 查看；收到回执不代表采集已成功。
没有新的服务、口令、数据库表或持续日志。桌面扩展不显示此卡片，也不运行这项诊断。
验证记录见[一次性诊断验收](verification.md#orion-capture)。

## 正常采集验收

完成安装和设置后，优先使用上面的固定公开页诊断：

1. 保持页面前台约一分钟，然后返回扩展设置发送诊断。
2. Agent 在网站核对本次手机的访问、正文和截图，不能只看心跳或待上传为零。
3. 同一页面未变化时，下一次采样不应增加快照；离开浏览器后的时间不计入浏览。

手机只需报告“已发送”。若平台仍返回异常，回执里的固定原因码会区分无回复、错误类型和缺失字段；
不需要复制私人网址、正文、口令或完整日志。Mac 原生结果与 WebKit 测试分别记录，不能代替手机结果。

## 记录与归档

- 前台累计十秒后首次采集，之后复用分钟检查。相同访问中，正文与画面没有明显变化就省略快照。
- Orion iOS 使用顶层页面的文档身份和可见状态。切 App、锁屏和浏览器暂停期间不承诺执行定时任务；
  返回前台后继续既有队列。新快照和结束访问持久入队后立即上传，失败继续使用原来的退避；后台暂停不保证网络请求完成。
- 标签切换、页面变化优先使用浏览器事件给出的 tab ID，再核对页面确实活跃且可见；不会为了取得
  手机不用的窗口 ID 先查询全部活跃标签。原生回调五秒未回答就释放调用，后续事件和分钟检查继续处理，
  不让一次查询卡住全部采集。设置里的超时说明与上传成功分别显示。
- 截图优先原生 WebP；浏览器不支持其编码时使用原生 JPEG。同样限制最长边 1920 像素、质量 0.75、384 KiB。
  截图失败时正文仍可保存，扩展显示具体结果。隐私名单、密码页和无痕排除继续适用。
- 两台设备访问同一网址会汇总到同一页面，但访问和快照分别保留设备来源；去重不会因另一台设备采集过而跳过。
  时间线可选全部设备或某一台，重叠时间仍按实际时间并集统计。
- 所有设备共用七天热文件窗口及同一 Dropbox 归档。只有正文和截图已确认归档后才从 R2 移出；
  搜索索引保留，旧快照直接从 Dropbox 读取。增加设备不需要增加备份服务。
- 手机显示最近连接、待上传和实际错误。连接成功可能只是空心跳；待上传为零表示队列为空，不能证明已经采集。实际访问记录在网站时间线按设备查看。一天没有打开浏览器不算上传故障。

## 本地验证

从仓库根运行：

```sh
bazel test //recall/extension:check
bazel test //recall/extension:browser_tests
```

Bazel 使用锁定的 Playwright WebKit archive，并执行真实构建的设置、后台和 probe 脚本。保存检查覆盖正常保存、
采集查询卡住、写入卡住和状态刷新卡住；采集检查验证加载事件及自动分钟 Alarm，经真实 DOM、IndexedDB、
JPEG 编码和 gzip 将合成正文/访问交给假消费者。丢弃文件注入完成值时仍须取得真实消息回复；未变内容不能新增快照。
测试使用自己的临时浏览器目录，不安装到日常 Chrome/Orion。Linux CI 的系统库准备也使用锁定 CLI。

Orion 使用文件注入安装顶层监听器，再由 `tabs.sendMessage` 请求当前可见性或正文。
前台识别和分钟恢复先询问已安装的当前版本监听器；新文档、监听器缺失或版本改变才安装。
同一采集中的正文、截图复核继续检查已知文档。注入完成通知缺失时只在首次安装等待既有的五秒上限，
同一网页的连续事件不重复等待。
正文读取前在内容脚本同步核对文档身份、已验证的网址、可见性及构建版本，页面跳转时不读取新页面。
注入未收到完成通知时仍需实际页面回复；界面不会把这条通知当作采集成功或失败。

上述消费者请求由本地测试截获，不访问生产 Recall。扩展 API 桥接与 `chrome.storage.local` 是 fixture；
DOM、脚本执行、IndexedDB、图片压缩与 gzip 是真实 WebKit。它不能证明 Orion 自己的 API 实现或 iOS 前后台挂起行为。
原生 Mac 与手机的分阶段验证见[验收记录](verification.md)。
临时观察包没有进入正式源码；当前回归使用已有 WebKit 检查，不需要安装测试扩展到日常浏览器。

设置里的“当前记录”描述当前前台页面；设置页本身不采集。“活动检查”能确认后台是否检查过页面，
“最近采样”始终显示结果或“尚未采样”，不再让空白状态掩盖尚未开始采集。最近错误只显示固定阶段码，
不包含网址、标题、正文或口令。

## 验证边界

本地 WebKit 的扩展 API 桥接是 fixture；DOM、脚本、IndexedDB、图片与 gzip 是真实引擎。它能验证代码的采集、
去重、保存/上传隔离和回调行为，不能证明 Orion 原生 API 或 iOS 挂起行为。实际手机只记录浏览器前台活动。
历史短时成功与后续故障分别保留在[验证记录](verification.md)，不作为当前稳定性结论。
