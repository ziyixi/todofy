## Tasks UI refinement, released

Implementation `6ef11633809bfefc2b2a4602bc71a53dbe1a7c2a`, branch `codex/tasks-design`, was based on
`43eb37bb` in `/private/tmp/todofy-tasks-design`. The owner's shared checkout was left untouched to avoid
conflicting with ongoing work.

- The compact Focus timer keeps the Step title, visible controls and cumulative time against the estimate.
  Taller windows show the parent outcome. It uses existing tokens and Lucide icons; the main timer bar's clock
  is slightly stronger. No new dependency, timer state or server requests.
- Save displays a check and Saved without moving the dialog. Description Done saves the current complete draft
  through the existing write, keeps it on failure and renders Markdown immediately. The existing renderer is
  eager so a cached reopen does not swap raw text for Markdown. Pending title/description input is disabled.
- Quick respects the Deadline start window as well as its existing Due selection. Zero lead opens on Deadline
  day; otherwise eligible active work remains available.
- Plan's Step estimate panel deletes a Step with inline confirmation through native DeleteTask. Existing
  queue/dependency deletion semantics and time records are retained.

## Approved Tasks interface

Implementation `53e0c2b1207cfd9d907f1e946a0c5c1bde6b7707`, branch `codex/tasks-interface`, was based on
`57a50db5` in the isolated worktree. The shared checkout remained untouched. The
[approved design and rendered comparison](../../tasks/design-qa.md) record desktop and 360 px acceptance.

- Task details now group Planning/Context, Execution, children and properties in the approved two-column layout.
  Execution is Steps, Standalone or Quick; Routine is independent. Native Tasks and Plan share the controlled
  `ExecutionFields` component. Their existing owners map it to existing flags; no schema or API was added.
- Manual In progress, Waiting, On hold and Parked controls are absent from the editors. Persisted flags, dates,
  estimates and dependencies retain their existing rules; unrelated saves preserve them. Choosing a stage still
  clears Parked. Existing Steps keep their timing and estimate controls.
- Navigation separates Tasks and Planning, keeps Favorites, remembers collapsed project branches, and places
  lower-frequency tools at the bottom. Existing routes, menus, category dragging, counts, keyboard shortcuts,
  archived browsing and resizable navigation remain available. Project grouping is computed once per render.
- Add step and Add subtask open their own inline composer. Repeated clicks focus the input; Escape returns to
  the trigger; successful Enter creation keeps focus for the next item. No new request, dependency or service.
