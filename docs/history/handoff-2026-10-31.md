## Bazel package ownership and shared build recipes

[PR #18](https://github.com/ziyixi/todofy/pull/18) moved implementation targets into their owning source, test and
script packages throughout the repository. Each application and project directory keeps its main build, check,
configuration, release and operator interfaces. Explicit dependencies and native test suites retain fine-grained
selection; related cyclic modules stay together. Generated output paths remain with their generator packages.

Shared Starlark recipes cover existing Python runners, project-scoped JS/browser tests, source/data providers,
Wrangler archives and source audits. BUILD files still own dependencies, fixtures and execution limits. The
ownership move exposed undeclared compiler config, implicit working directories, declaration-file copying and
generated-package link assumptions. Those build boundaries are now explicit. Application runtime logic, test
coverage and execution limits remain intact; source guards recognize regular BUILD metadata in its new locations.

## Newsletter configuration after granular CI

The [documentation follow-up](https://github.com/ziyixi/todofy/actions/runs/41157241329) exposed an old publication
assumption: source compatibility was compared with the last image's whole repository revision. Unrelated green
changes could therefore block configuration updates once Bazel correctly stopped rebuilding unaffected images.

[PR #20](https://github.com/ziyixi/todofy/pull/20) compares configuration against the latest successful main source
once, then selects an image with an actual successful publication. The source anchor and image identity may differ.
Untested mixed source changes still defer. Direct configuration pushes, post-CI recovery, image validation and
publication checks keep their existing paths; no additional state or workflow is introduced.

Native regressions reproduced the original lookup and subsequent-update failures. All 56 publication cases and
Ruff checks passed, including deferred configuration recovering after a successful CI that published no new image.
Independent review and [final branch CI](https://github.com/ziyixi/todofy/actions/runs/41158883379), including the
actual Linux container probe, passed at `80b5095a`. No application release artifacts were selected.

The merged correction `8f5b83fb` passed [main CI](https://github.com/ziyixi/todofy/actions/runs/41159253141)
and [same-source reconciliation](https://github.com/ziyixi/todofy/actions/runs/41159551786); no application artifact
or deployment was selected. Its real [configuration follow-up](https://github.com/ziyixi/todofy/actions/runs/41159551795)
executed both image validation and bundle publication successfully. It used the actual image from `eb3a983c`
to validate source `8f5b83fb`, and published the bundle without a stale skip, deployment or email.
