# 规划界面与接口说明

Tasks 的 Plan、Focus 和邮件归类对话框由本包提供（[README](../README.md)）；宿主见 [Tasks](../../../tasks/README.md)，原生验收见[对照表](../../../tasks/docs/planning-parity.md)。文中的标记（`waiting`、`blocked`、`parked`、`onhold`、`quick`、`active` 等）是 Tasks 任务的规划标记（planning flags），不是普通标签；“规划范围”是任务保存的 stage。日期是各项 owner 定稿的日期；2026-10-17 以前的定稿最初做在已退役的 Todoist Plus 扩展里（[历史](../../../docs/history/todoist-plus.md)）。代码路径相对本包。

## Plan 的组成

Plan 顶部保留当前账户周的本周目标，下方有 Review 和 Week 两个视图。第一次打开默认 Review 和 All，工作／生活过滤不改变任务。浏览另一周只影响 Week 的日期队列，不把当前承诺或本周目标伪装成历史快照。

卡片左边的色条是领域（2026-10-19 owner 决定），Plan 和 Focus 只用这一条规则（`areaColor`，`src/planning-outcomes.ts`）：按任务的领域，自己的，否则最近一层父任务的。工作是 `--plus-area-work`（#6387a3，灰蓝），生活是 `--plus-area-personal`（#a98369，赭石），未分类不着色，只是卡片自己的边线色 `--plus-line`。它用在 Review 和 Week 的事项卡（含选中的）、“下一步”托盘的标题条和步骤卡、快速事项、日历里的步骤、Week 的拖动浮层、Focus 的卡片和所属任务条上；元素设 `--area-color`，CSS 一律读 `var(--area-color, var(--plus-area-none))`。Plan 不列出的任务（FlowDay 的本地记录）不着色。Review 和 Week 的领域过滤里，“工作”“生活”标签前的 8px 圆点就是图例，“全部”“未分类”没有圆点。颜色不单独表达领域：事项卡的可访问名称带领域，快速事项的标题按钮末尾有只给读屏的领域（`, Work`／`，工作`），下一步属于托盘标题里的事项，日历卡片下一行写着所属事项或领域。工作和生活的色条对 `--plus-bg` 约 3.8:1 和 3.2:1，满足非文字界面的 3:1。

Review／Week、Review 的领域过滤、本周周回顾是否展开及勾选、Week 选中的承诺和“本周承诺”的折叠由宿主保存（Tasks 存在浏览器 localStorage 的 `tasks.plan-view`，只有 ID 和行号，按字段合并写入），离开再回来、浏览器后退和刷新后恢复（2026-10-17 owner 决定）。Plan 挂载时读一次，之后只在用户改动时写入改动的字段，单纯打开不写入。记住的承诺已不在本周承诺里时选第一个，记住的领域不再出现在过滤里时显示全部；读不到时用默认值，存不进时页面照常工作。Week 自己的领域过滤不记住。同一字段在两个标签页里先后改动时以后改的为准。

### 本周目标

2026-10-16 owner 定稿：工作、生活各一行用户自己写的文字（最多 160 个 UTF-16 单位），原地编辑，存在 Todofy 的规划库（D1 `plan_notes`，kind `bets`，按账户周一和领域），不写入任何任务，与任何任务、承诺或标签都没有关联。

- 位置不变，在 Review／Week 上方；两列“工作／Work”“生活／Personal”，窄于 650px 时上下排列；只显示当前账户周，Week 翻到别的周不跟着变。
- 已写：目标文字本身就是编辑按钮（14px、600、可换行、纯文本、不识别链接），悬停时 `--plus-hover` 底色和文字光标，没有铅笔图标；按钮名 `编辑工作目标：{text}`／`Edit work goal: {text}`。
- 空：13px 灰字按钮“写下这周的工作目标”／“Write this week's work goal”（生活同理）。
- 空、上周有：下面多一行 12px 灰字“上周：{text}”，单行省略，完整内容在 `title`；悬停或焦点在这一列时旁边出现强调色的“沿用／Keep”，没有悬停的设备上一直显示；按钮名 `沿用上周的工作目标：{text}`。点一下把上周的文字写成本周的，焦点落在保存好的目标上。这是延续目标的唯一入口。
- 编辑中：原地换成同字号、同位置的一行输入框（`maxlength=160`），占位“这周最想推进的一件事”，标签“本周工作目标”，提示“回车保存 · Esc 取消”（输入框的 `aria-describedby`），剩 20 字以内时加“ · 还可输入 {n} 字”。计划页里提示放在这一列标题行的右端，整块高度不变，下面的看板不动；周回顾里仍在输入框下面一行。保存中输入框只读，末端显示 PendingMark“正在更新…”。
- 焦点框画在目标按钮内侧（`outline-offset: −1px`，同输入框），按 Enter、Esc 或“沿用”回到目标时不压到上面的列标题。
- 别处改过（ETAG_MISMATCH）：输入框下一行 `role=alert`“这条目标已在别处改过。再按回车会用你的文字替换它；按 Esc 查看最新内容。”，草稿保留，同时重读一次 ReadPlan 显示最新内容；之后只有 Enter 或 Esc 决定。
- 这一周已结束（ACTION_NOT_ALLOWED）：`role=alert`“这一周已经结束，没有保存。”，草稿留着，Enter 不再写入，Esc 关掉；随后后台重读新的一周。
- 保存失败：现有横幅“未确认保存成功，请重试。”，草稿留在输入框里。
- 未配置、断开或维护中：现有 fieldset 停用，横幅不变，目标文字照常可读。

什么时候保存（`src/BetText.tsx`）：

- 在目标上按 Enter 或 Space 打开编辑框，光标放在末尾。
- Enter 保存；输入法组字时的 Enter（`isComposing` 或 keyCode 229）不算，中文输入不会提前保存。文字没改时直接关掉，不写入。
- Tab 或点页面里别的地方：文字改过且不为空就保存，焦点不动。切换窗口、切到别的应用或标签页被隐藏（`document.hasFocus()` 为 false）不保存，草稿保持打开；Plan 被重新挂载时草稿丢弃，也不写入。
- 离开时框是空的不清空，恢复原来的文字；只有在空框里按 Enter 才清空这一周的目标（保留这一行，正文为空，rev 加 1）。
- Esc 取消，恢复原文，焦点回到目标。
- 按 Enter 或点“沿用”之后焦点落在保存好的目标上；因离开而保存时焦点不动。
- Tab 顺序：工作目标 →（沿用）→ 生活目标 →（沿用）。每列标题是 h3，整块的 aria-label 仍是“本周目标”。
- 结果由隐藏的 `role=status` 读出：“已保存工作目标”“已清空工作目标”“已沿用上周的工作目标”（生活同理）。这个区域一直在，只换文字（`src/announce.ts`）；同一句话连着出现两次时先清空、100ms 后再写，第二次也会被读出。
- 其他写入等待确认时，目标和“沿用”只用 `aria-disabled` 标为不可用（目标变暗、“沿用”变灰且仍只在悬停或焦点时出现，点击无效），不用 `disabled`：否则 Tab 刚移到另一行目标上的焦点会被它自己那次保存夺走。

写入是 SetWeeklyBet：只写 D1，不写任务，也没有回执；先比较，文字与已存相同就直接返回已存的目标（所以丢失回答后的重发、跨过周日午夜的重放都安全，请求不带 request ID），否则只接受本周和下周，再按 rev（etag）写入一条。返回的 WeeklyBet 直接合并进 `plan.weeklyBets`，不再读取。ReadPlan（FULL）在周回顾那一批 D1 查询里多一条，返回上周、本周和下周的目标，最多 6 行。

### Review

2026-10-16 owner 定稿，2026-10-17 加入“搁置”，2026-10-18 本周承诺改为单独一行：从左到右是“该开始／Start now”、“等待中／Waiting”、“搁置／Parked”和三个规划列 Quarter、Month、Week（本季度、本月、本周），各自竖排；第四个规划列 Committed（本周承诺）在它们下方单独占满一整行，卡片横向排列，每行的卡片数与上方的列数相同。前两列没有卡片时整列不渲染。“搁置”和规划列一样始终显示，空时写“拖到这里搁置／Drop here to park”，与其他列同样大小：接受投放的列若到拖动开始才出现，会把正在瞄准的列挤开。没有新标签页。宽窗口里上方的三到六列排成一行；内容区窄于约 800px 时每行两列，窄于约 430px 时一列；本周承诺始终另起一行（`src/review-board.css`）。各列用同一种列和事项卡，样式相同。

每个任务只在一列出现，取第一条命中的规则（`src/review-lanes.ts`）：

0. 带 `parked` 标记：搁置，无论它有没有规划范围、在不在等或该不该开始。所以它也不在任何承诺列表里（Week 的总览、工具栏的数量、周回顾），不是 Week 的下一步，也不算“等待中”。
1. 有自己保存的规划范围（本季度、本月、本周、本周承诺）：留在该列。它在等或该开始时，卡片用一句安静的状态说明，见[截止日期](#截止日期)和[等待中](#等待中)。
2. `waiting` 或 `blocked` 标记，或在等另一个尚未完成的任务（[依赖](#依赖)）：等待中。
3. 启动窗口已开或已过截止，且不是进行中：该开始。只因 7 天日期规则（Candidate If）成为 Week 待选的任务也进该开始，不进 Week。
4. 其余按原有日期规则留在 Week。

小步骤不是所属事项那一列的卡片，即使保存了同一个规划范围，它也只是事项卡里的一步；所以在等或该开始的小步骤在“等待中”或“该开始”有自己的卡。投放有落点检查：按预测写入后，卡片必须在目标列里，否则这次投放不写入，卡片回到原处。所以把这样的卡（或搁置的小步骤）拖进所属事项的列不写入：写入后它会回到原列，或只是事项卡里的一步。只有从“该开始”拖入并标为进行中是确认，照常写入：它可以离开看板，只是不能回到“该开始”。拖入别的规划列（在那里成为自己的卡）照常写入。

事项卡固定高度，领域看左边颜色（2026-10-19 owner 决定）：每张事项卡（Review 各列、Week 的承诺总览和拖动浮层）都是 77px 高，上面是最多两行的标题，下面是钉在底部、靠左的一行 12px 文字：步骤及排程数量，或在等、该开始的卡片换成的一句 muted 状态，“搁置”里的卡片换成“N 天未变动”（它在等时仍写在等；搁置的任务从不“该开始”）。这一行从不换行，太窄时以省略号结尾，所以任何宽度下卡片都一样高；标题只有一行时，标题下面留白。卡片上不再写“工作／生活”：领域由左边色条表示（见[Plan 的组成](#plan-的组成)），可访问名称是“标题, 领域, 优先级”加状态。标题被截断时，鼠标悬停或键盘焦点停在卡片上约 350ms 后，标题下方浮出完整标题（`src/FullTitle.tsx`），卡片不再带 `title`。“搁置”按最久未变动排在前，只先显示前 3 张（侧边的列在规划列上方时，一堆搁置的卡不会把规划列挤出屏幕），其余收在一行 12px 强调色的“再显示 N 项／N more”后面，展开后是“收起／Show fewer”，只是这次显示的状态。状态有两段时合成一行，截止日期那一段在前（`10月22日截止 · 12 天未变动`、`已过 2 天 · 等「订场地」`），所以红色的“已过 N 天”不会被截掉；完整的一句仍在可访问名称里，截止日期的完整日期仍是状态的 `title`。拖动时浮起的卡片与原卡同宽同高（dnd-kit 按原卡设定浮层尺寸），也带抓手。优先级保留其原值，用 14px 旗标和原有优先级颜色表示；静止卡片只用细边线，拖动浮层保留阴影。整体目标不再以每张承诺卡的星标呈现。标题点击打开任务详情；单独抓手拖动卡片。落在同一列的卡片上调整这一列的顺序（见下段），落在同一列的空白处无变化；跨规划列仅调用该任务的规划范围写入。从“该开始”拖入任一规划列就是确认：同一次 SetTaskPlan 写入该列的规划范围和 `active`。从“等待中”拖入只写规划范围，不去掉 `waiting`／`blocked`，也不加 `active`。拖入“搁置”只发 SetTaskPlan `{parked: true}`：加上 `parked`，Todofy 同时去掉规划范围和 `active`（从“该开始”拖入也不标为进行中）；从“搁置”拖入规划列发 `{stage, parked: false}`，写入该列的规划范围并去掉 `parked`；在任务详情（点搁置卡片的标题打开）里给它选一个规划范围后保存，或点“标为进行中”，同样带 `parked: false`，它随之离开“搁置”，只改领域时不带。“该开始”和“等待中”不接受投放，落在上面的卡片（包括来自“搁置”的）回到原处。拖动都先显示、按序保存，失败时撤回，见[写入与读取](#写入与读取)。卡片不移动整棵子树。

每一列都可拖动或用键盘调整顺序（2026-10-17 owner 决定）。只有落在同一列的卡片上才换位置：被拖的卡占据那张卡的位置（向上或向左移时在它前面，向下或向右移时在它后面），落在列的空白处、标题或缝隙里不变。拖到同列另一张卡上时，那张卡的上方或下方（本周承诺一行里是左侧或右侧）出现日历同样的 3px 强调色插入线，标出真正的落点；拖动期间页面不移动任何卡片，落下前看到的顺序就是数据的顺序。拖到别的列（接受投放的规划列或“搁置”）时那一列照旧着色。键盘：抓手上按空格或回车拿起，方向键移到那个方向的下一张卡或下一列（本周承诺一行里左右键在卡片间移动，从上方的列按下键进入它），空格或回车放下，Esc 取消；落下后焦点留在被移动卡片的抓手上。读屏按页面语言读出卡片标题、列名和位置，例如“已拿起：订场地”“移到：本周承诺第 2 项”“已放下：订场地”，从不读出内部 ID。每个抓手（Review 的卡片，Week 的步骤、快速事项和日历里的步骤）的描述是同一句操作说明“按空格或回车拿起，方向键移动，空格或回车放下，Esc 取消。”，角色说明是“可拖动／draggable”：说明放在看板自己的隐藏元素里，只作描述。切换页面语言时拖动区重新挂载，说明和播报都换成新的语言。

顺序存在 Todofy 的规划库（`plan_settings` 的 `board`）。每列先按存好的顺序（已不在这一列的 ID 跳过），其余的按这一列原来的顺序排在后面；“该开始”相反，其余的排在前面，新到期的任务是最要紧的消息。原来的顺序：该开始按截止日期和优先级，等待中和搁置按最久未变动，规划列按事项顺序。跨列投放只写规划范围，卡片排在新列已排好的卡片之后（“该开始”是之前），除非新列存好的顺序里还留着它以前的位置。每列最多存 100 个：移到第 100 个之后的投放不保存。该开始和四个规划列同步到 Tasks：被移动卡片在这一列里的同一项目、分区和父任务下的兄弟任务按列中顺序交换原有的位置（`sort_order`），其他任务不动，这一列里只有它自己时任务不变；等待中和搁置只存在 Todofy（它们按“未变动天数”排序，不写任务）。每次投放一次 ReorderTasks，先显示、按序保存，失败时撤回。Week 的承诺总览与“本周承诺”一列同序。

完成勾选框（2026-10-18 owner 决定）：Review 和 Week 承诺总览的事项卡、下一步托盘的步骤、快速事项和日历里的步骤都有 Tasks 同样的圆形勾选框（`src/CompleteTaskButton.tsx`），可访问名称“完成：标题”／`Complete task: …`，在 Tab 顺序中位于卡片之后、“开始”之前。它与 Focus 的完成是同一次写入（Tasks 完成，再结算 FlowDay），重试沿用同一个请求 ID；日历里的步骤带它所在的 FlowDay 日期，其余带今天。写入期间或卡片等待确认时停用；完成后卡片在重新读取后离开。带 `quick` 的任务总是可以单独排进日期：Quick 隐含“作为步骤安排”，任务详情里这一项在 Quick 时保持勾选、不能取消。

### Week

上方紧凑总览显示当前 Committed 事项，与 Review 的“本周承诺”一列是同一组、同一顺序（搁置的不在其中）。默认展示全部，工作／生活过滤保持可选。点击一个事项展开它的小步骤，再从步骤托盘拖入日期。没有自己规划范围的中间层级和仅因日期进入候选的子步骤继续属于父事项；保存了不同规划范围的子事项按自身范围处理。只有步骤（`kind=step`）和标记为“作为步骤安排”的任务能排进日期。日期不重写。

步骤卡先显示标题，下方显示短所属事项和估时；左边色条是领域（见[Plan 的组成](#plan-的组成)）。事项卡与 Review 的同高（77px），标题最多两行，被截断时悬停或键盘焦点显示全文。本周承诺全部显示，超过一行自动换行；5/3 只是提示。网格按宽度排列，每张卡至少 220px：1440px 窗口 4 列，1024px 3 列，800px 和 680px 2 列。步骤卡按内容排布，不按估时把普通卡片拉成占满屏幕的长块。实际数据没有额外保存色彩设置或像素布局。

### 截止日期

2026-10-16 owner 定稿，取代同日第一版的“截止日期 · N”列表（设计 §1、§3）。截止日期按一条生命周期看：截止日期 → 启动窗口 → 进行中 → 完成。任务有截止日期和提前开始的天数（0–365）；从截止日期前 N 天起（Todofy 的 `must_start` 规则，已过截止也算）它出现在看板上，在此之前不出现。确认后它带上 `active` 标记，不再显示为该开始。没有新页面、新语法或新图标；唯一的颜色是“已过 N 天”的 `--plus-danger`。

`src/deadlines.ts` 在完整读取之后，按 Todofy 给出的 `must_start`、`missing_lead` 和 `active`、`blocked`、`parked` 标记，给每个有截止日期、且未搁置的任务一个状态，取第一条命中的规则：

| #   | 条件                                | 状态         | 出现在                                         |
| --- | ----------------------------------- | ------------ | ---------------------------------------------- |
| 1   | `active` 标记，且没有 `blocked`     | 进行中       | 不占看板的列；任务详情写 `进行中 · 还剩 12 天` |
| 2   | `must_start`，截止日期早于今天      | 已过截止     | 该开始，或它自己的规划列                       |
| 3   | `must_start`                        | 已到启动窗口 | 同上                                           |
| 4   | `missing_lead`                      | 未设提前量   | 只在周回顾的一行，见[周回顾](#周回顾)          |
| 5   | 其余（窗口未到）                    | —            | 不出现，只在任务详情说明                       |

`waiting`／`blocked` 标记和尚未满足的[依赖](#依赖)在列的规则中优先：已过截止、带 `waiting` 的任务（`must_start` 包含它）在“等待中”，在等另一个任务、启动窗口已开的任务也在“等待中”，不在“该开始”。

“该开始”按截止日期从早到晚，同一天按优先级。卡片是标题和一句状态（领域在左边色条和可访问名称里）：`还剩 5 天`、`明天截止`、`今天截止` 或 `已过 2 天`（danger）；英文为 `5 days left`、`Deadline tomorrow`、`Deadline today`、`2 days late`。有规划范围的卡在自己的列写同一句。完整日期是状态的 `title`（`截止日期：10月11日周日`）；读屏只补上状态没说的部分：状态已写日期时只加星期（`11月30日截止，周一`），否则加完整日期（`已过 2 天，10月11日周日`）。

确认有两种：把卡片从“该开始”拖入某个规划列（规划范围和 `active` 一次写入，见 [Review](#review)），或用卡片的悬停操作“开始／Start”，只加 `active`。“开始”平时不占位置，标题用满卡片宽度；只在鼠标悬停或键盘焦点（`:focus-visible`）进入该卡时出现在标题第一行的右端，标题在它下面淡入卡片自己的底色。它只用透明度隐藏，不挪动标题和状态，仍在 Tab 顺序（卡片和完成勾选框之后）和可访问树里，可访问名称为“开始：标题”；不能用时（写入期间、拖动未确认）停用并保持隐藏。没有悬停能力的设备一直显示，盖住标题第一行的末端。有规划范围、在启动窗口里的卡也有“开始”。它是先确认的 SetTaskPlan `{active: true}` 写入：确认后合并返回的任务，不再整表读取；“该开始”里的卡离开看板（该列空了就整列消失），有规划范围的卡留在原列、状态消失。焦点移到下一张卡的“开始”，没有了就回到该卡或看板第一张卡；看板旁的 `role="status"` 读出“已标为进行中：标题”。事项卡的拖动尚未确认时，它还带着拖动前的 etag，所以“开始”先停用。

已过截止或已到启动窗口的任务本身和它未完成的小步骤都不在本周已读取的 7 天队列里时，Focus 摘要下方有一行安静文字，见[Focus 与计时](#focus-与计时)。Week 的承诺总览用同一张事项卡，但始终显示步骤和排程数量，不写在等或该开始的状态：那里是安排步骤的地方。不把启动窗口里的任务投进 Week 列。

有截止日期但没设提前开始的任务只在周回顾出现一行“N 项截止还没设提前量”；展开后每项可直接用任务详情的同一个提前量下拉框选择，看板和其他地方都不显示。已过截止、又没设提前量的任务按规则 2 也在“该开始”。

### 等待中

“等待中”是 Review 的第二列，紧挨“该开始”右侧，只在有没有自己规划范围、带 `waiting` 或 `blocked` 标记或在等另一个任务的任务时出现（搁置的任务在“搁置”，不在这里，周回顾的计数同样不算它们）；有规划范围的在等任务留在自己的列，卡片写同一句状态。在等另一个任务时，“N 天未变动”换成 `等「订场地」`（多个时 `等 2 项`；英文 `Waiting for “Book venue”`、`Waiting for 2 tasks`），截止日期那一段照旧，见[依赖](#依赖)。卡片按任务的最后修改时间排列，最久未变动的在前，状态为“12 天未变动”（按满 24 小时计，不足一天为“1 天内有变动”；英文 `No change in 12 days`、`Changed within a day`）；有截止日期时前面加截止日期那一段：`10月22日截止 · 12 天未变动`（英文 `Deadline Oct 22 · No change in 12 days`），已过截止是 `已过 2 天 · 12 天未变动`（danger，与“该开始”同一句，看板上只有这一种红字），两段合成一行，截止那一段在前。由此承接原来按截止日期列出等待任务的筛选器。任何编辑都会重置这个时间，所以它不表示已等待多久，也不推断在等谁。

卡片没有悬停操作：点击标题打开任务详情（那里仍可添加步骤、加入今天和打开完整任务），拖入规划列只写规划范围。它不移除标记、不联系任何人，也没有新的存储。

### 依赖

2026-10-16 owner 定稿（设计 plus-next §2，数据层 §5.1）：一个任务可以等其他任务完成。依赖只存在 Todofy 的规划库里，是两个任务 ID 之间的一条边；不写进任务的标题、描述或标签，也不设 `blocked`。它只影响显示：所等的任务完成后，这个任务显示为可以开始，不改日期、不加减标签。旧标题后缀 `<k:… dep:…>` 在 Plan 里隐藏。

规则（`src/dependencies.ts`，完整读取之后）：

- 所等的任务 B 在活动列表里就在等；B 不在活动列表里就算满足（“消失即满足”），无论它是完成还是删除，Todofy 随后核对是哪一种。被重新打开的 B 又出现在列表里时重新算在等。
- 循环任务完成时只推进日期、ID 不变：任务的 `completed_count` 在每次完成时加一、撤销时减一。建立依赖时 Todofy 记下 B 当时的计数，B 在那之后的下一次完成（计数大于记下的值）就算满足，以后的循环不再挡住 A；要等 B 的再下一次，就在选择框里再选一次 B，Todofy 从当时的计数重新记起。没有计数的循环任务不能被选作依赖。
- 只有仍在等的依赖算数：每个任务最多等 5 项，全部最多 300 条；不能等自己，也不能互相等待（含经过其他任务的环）。已满足的依赖不构成环，也不占 5 项：任务已有 5 条（或全部已有 300 条）时，它最早一条已满足的依赖给新的让位。选择时就不让选，Todofy 在锁内用一次读取判断哪些依赖仍在等，再查一次。

**任务详情的“依赖 / Depends on”段**：在 Plan 的任务详情里，位于“截止日期”段之后，标题样式与“下一步”“截止日期”相同。

- 每个尚未满足的依赖一行：13px 标题按钮（在 Plan 中打开它的编辑器），循环任务右侧写 `下一次完成后 / After its next completion`；最右是 24px 的 ×，可访问名称 `移除依赖：订场地`，平时透明度为 0，只在悬停或键盘焦点进入这一行时出现，没有悬停能力的设备一直显示。
- 已满足的不逐条列出：全部满足时写 `所等的任务都已完成，可以开始了 / Everything it waits for is done — ready to start`，部分满足时 `另有 1 项已完成 / 1 more is done`。这一行右端同样有 24px 的 ×（`移除已完成的依赖 / Remove the done dependencies`），只在悬停或键盘焦点时出现，一次排队写入移除这些已满足的依赖，读出 `已移除已完成的依赖`。不移除时，它们在这个任务离开活动列表后由 Todofy 删除，或给新依赖让位；循环任务一直在列表里，所以这一行会留到移除或被新依赖替换为止。
- 有任务在等它时多一行只读文字：`「发邀请函」在等它`，多个时 `「发邀请函」等 2 项在等它`。
- `+ 添加依赖 / Add a dependency` 是 `.plus-text-button`；已有 5 项仍在等时停用，`title` 为 `最多 5 项 / Up to 5`。
- 行高 32px（含下边线），带 × 的已保存行和带等待标记的待确认行一样高，确认时不跳动。标题按钮平时像普通文字，悬停或键盘焦点时加下划线，表示点它会打开那个任务。

输入法组字期间，Enter、方向键和 Escape 交由输入法处理，不移动选项或添加依赖。选择框是内联的，不在 Plan 的对话框里再套一层：32px 输入框自动获得焦点，占位文字 `搜索任务或父任务 / Search tasks or parents`；输入后在已完整读取的活动任务中按标题或父任务即时搜索，规则与原“更换目标”相同，没有语法；没有输入时不列出任何任务。结果最多 6 行，每行至少 28px：标题 13px，右侧是父任务路径（12px muted）。不列出任务自己、它的父任务和它的步骤，以及它仍在等的任务；已满足的循环任务会再列出，选它就等它的下一次完成。会形成循环的任务（按仍在等的依赖）仍列出但为灰色，右侧写 `会互相等待 / Would wait on each other`；没有计数的循环任务同样灰色，写 `重复任务不会结束 / Repeats, never finishes`；灰色的行不能选择，也从不高亮：高亮从第一个能选的行开始，↑↓ 只在能选的行之间移动，鼠标移到灰色行上不改变高亮，Enter 添加高亮的那一行；Escape 或 `取消 / Cancel` 收起选择框，Escape 不再传给外面的对话框，焦点回到“添加依赖”。

选中即写入，是先确认的 SetTaskDependency：新行先带现有的等待标记（PendingMark）显示，写入期间停用写入控件，确认后合并返回的这个任务的依赖，不再整表读取；编辑器的 `role="status"` 读出 `已添加依赖：订场地`。点 × 同样是一次写入，读出 `已移除依赖：订场地`。失败时用原有错误区域：Todofy 拒绝时写 `Not added: this dependency cannot be added now. Refresh and try again.`（别的标签页刚改过依赖、规划未启用或任务写入暂停都是同一个拒绝，所以不猜原因；和其他 API 错误一样只有英文），任务已不在活动列表时写 `Not added: one of these tasks is no longer active. Refresh and try again.`。

**看板与其他位置**：只因依赖而在等、又没有自己规划范围的任务在“等待中”，排序规则不变（最久未变动的在前）；有自己规划范围的留在原列。卡片计数那一段换成一句安静的状态 `等「订场地」`／`等 2 项`，有截止日期时截止日期那一段在它前面（`已过 2 天 · 等「订场地」`），可访问名称带同一句和完整标题；在等的卡片没有“开始”。所等任务的标题最宽 7em（中文约 7 个字），太长时在引号里以省略号结尾，引号保留，悬停提示完整标题；整句只占一行，卡片窄时以省略号结尾，不会溢出卡片。Focus 的那一行和周回顾的“等待中”计数都包含这类任务；Week 的承诺总览照旧只显示步骤和排程数。

**核对**：只有 Plan 的 Review 看板显示核对的提示，所以只有它核对：它每显示一次新的完整读取，若有依赖提到、但这次读取里没有的任务（先是等待方，再是还没确认完成的被等任务），或记为已完成、却又出现在读取里的被等任务（被重新打开），就在后台调用一次 ResolveDependencies，最多 20 个 ID；同一次页面访问里每个 ID 只问一次，已问过的不占名额，其余的在下次完整读取时轮到；失败的在下次完整读取时再问。Focus 和 Week 从不调用，所以一次性的提示不会在看不到的地方用掉。Todofy 先向 Tasks 确认哪些在活动列表里：被重新打开的重新记为未关闭；消失的等待方删除它的依赖；被等任务按 Tasks 的完成记录记为完成，删除时删掉等它的依赖；说不出（没有完成或删除的记录，例如归档项目里的任务）时不作任何记录，同样删掉等它的依赖。提示在本次页面访问内出现一次，位于看板各列下方（不在上方，出现时看板不移动），12px muted：删除时 `「整理书架」等的任务已被删除，不再等待。`／`“Tidy the bookshelf” no longer waits — the task it waited for was deleted.`，说不出时 `「整理书架」等的任务已不在待办中，不再等待。`／`“Tidy the bookshelf” no longer waits — the task it waited for is no longer active.`；即使“等待中”已经没有任务也显示，由 `role="status"` 读出；刷新页面后不再出现，没有确认或按钮。

### 周回顾

工具栏的“周回顾”打开一个五行清单，有截止日期没设提前量时多一行；Todofy 的周日回顾任务链接到 Tasks 的 `/?review=1#/plan`，打开 Plan 并展开清单一次，链接参数随即去掉。每行显示数量和跳转目标：

| 行             | 数量                                                                                                                                         | 跳转或操作                                                                                            |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 邮件待理清     | Todofy 还没转成任务的邮件（ReadPlan 的 `mailbox_pending_count`） | “打开”切到 Tasks 的邮件页；回到 Plan 时清单、勾选和所在视图都还在 |
| 等待中         | 同“等待中”一列（含在等另一个任务的任务），另显示最久未变动的天数                                                                             | 切到 Review（全部领域），焦点移到“等待中”一列                                                         |
| 承诺未安排     | 同 Week 的“这 7 天还没有安排”                                                                                                                | 切到 Week，范围回到“全部”，选中第一个这样的承诺，展开“本周承诺”，打开它的“添加步骤”输入框             |
| 将来／也许     | 本周还要看的带 `parked`、`onhold` 标记的任务：不含已在本月和本周已保留的，最久未变动的在前，一次显示 10 项                                         | 每项“移到本月”（SetTaskPlan，确认后保存；带 `parked` 的同时去掉它）或“保留”（不写任务）          |
| 下周承诺与目标 | 周日显示周日规则，可展开本周承诺，下面固定两行写下周的工作、生活目标；其他日子只有一行“周日可在这里选留到下周的承诺，并写下周目标”，不可勾选 | 周日每项承诺“留到下周”，两行目标原地编辑，见下节                                                      |

“N 项截止还没设提前量”只在 N 大于 0 时出现，排在“等待中”之后：展开后每项是标题（点击打开编辑器）、截止日期（`11月30日截止`，已过截止为 danger 的 `已过截止 2 天`）和任务详情的同一个提前量下拉框，选择即一次 SetTaskLead 写入，确认后该项离开列表，焦点移到同一位置的下一项，列表空了就回到清单标题；结果由 `role="status"` 读出“已设提前量：标题”。它的勾选单独存为第 6 行，不改变第 1 至 5 行已保存的编号。

第 1 行数 Todofy 还没处理的邮件，不数 Tasks 收件箱里的任务。

第 1 至 4 行和出现时的提前量一行可以勾选，第 5 行只在周日可以勾选。展开状态、勾选和“保留”按账户周随 Plan 的视图保存（见 [Plan 的组成](#plan-的组成)），只含行号和任务 ID；换一周重新开始（默认收起）。从回顾任务的链接打开后链接参数随即去掉，刷新或后退不会重新展开已关闭的清单。数据来自已读取的任务、七日队列和 ReadPlan，打开清单不增加请求。“完成回顾”只在点击时完成 Todofy 的回顾任务（CompleteTask，不带 FlowDay 日期），确认后才显示已完成；没有回顾任务或已完成时只显示状态。清单不预先选择、不自动应用，也不调用模型。

键盘与读屏：“移到本月”“保留”“留到下周”的可访问名称带任务标题，列表按钮至少 24px 高。保留或移到本月后该项离开列表，焦点移到同一位置的下一项，列表空了就回到该行；留到下周后焦点移到下一个仍可保留的事项，没有了就移到“收起”；完成回顾后焦点回到清单标题。每个结果另由一处 `role="status"` 读出，例如“已留到下周：标题”。关闭清单后焦点回到工具栏的“周回顾”。

### 周日选择留到下周

在账户时区的周日，在 Plan 里把事项设为本周承诺，Todofy 把它记为下周的选择，周一 00:00 的重置会保留它的承诺；再下一个周一按普通承诺处理。只有 Plan 的规划写入（SetTaskPlan）算数。本周更早做出的承诺照常在周一重置。目标是文字，按周保存，从不被重置。

周日清单第 5 行标题是“下周承诺与目标／Next week's commitments and goals”，说明：“在 Plan 中周日选的承诺会留到下周，其余的周一照常重置。目标按周保存，不会被清除。”

- 展开按钮“选要留到下周的承诺（{n}）”只列承诺；周日想保留一个已在本周承诺中的事项，点“留到下周”：它再发送一次同样的承诺写入，规划范围不变时 Todofy 不改任务。看板中周日拖入本周承诺，确认后清单立即显示为“已留到下周”，不再提供重复写入；已留下的事项之后在周日被移除承诺，就不再留到下周。
- 下面固定两行（`.weekly-review-items` 的样式）：先是灰色的“工作”“生活”，再是下周目标，编辑方式同上；空时“写下周的工作目标”，输入框标签“下周工作目标”，按钮名“编辑下周工作目标：{text}”。这里不放“沿用本周”：沿用只有一个入口，就是周一起空着的本周目标旁的“上周：… · 沿用”。

任务详情只发送用户改动的字段，周日只改领域不会把承诺误留到下周。后端规则见 [Todofy 的规划接口](../../../todofy/docs/planning-api.md#weekly-rollover-and-controls)。

## Focus 与计时

Focus 显示真实今天的未完成 FlowDay 队列，顺序与 Week 相同。卡片标题在上方，短所属事项、估时和计时信息在下方。空队列只有“调整计划”入口，不出现另一套任务挑选器。

摘要下方可能有一行安静文字（样式同 Week 的承诺提示，12px muted，悬停时强调色加下划线，没有图标），例如“1 项已过截止、2 项已到启动窗口，这周还没有安排”／“1 past deadline and 2 in their start window, not planned this week”。只有“已过截止”或“已到启动窗口”、又不带 `waiting`／`blocked`、也不在等另一个任务的任务（与看板一致：已过截止的在等任务在“等待中”）本身和它未完成的小步骤都不在本周已读取的 7 天队列里时才出现，每个任务只数一次，有自己规划范围、在原列写明状态的也算，所以数目可能多于“该开始”一列的卡片；Plan 正在看别的周时只看今天的队列；队列为空时也显示。点击打开 Plan › Review（全部领域），焦点放在“该开始”一列上；该列为空时（该开始的任务都有自己的规划范围）放在第一张该开始的卡上。按钮提示“在计划中查看”。它只提示，不往队列里加任何东西。

每个 Tasks 步骤显示独立的完成控件和计时按钮。队列不空时摘要旁可选计时方式：25 分钟、50 分钟或正计时，默认 25 分钟，开始时按它启动。完成控件是优先级圆圈（P1 红、P2 橙、P3 蓝带浅色底，P4 灰），与 Review 卡片一致；没有完成控件的 FlowDay 记录保留同宽空位，标题对齐。运行后显示确认的经过时间及 Pause、Stop；暂停后状态写“已暂停／Paused”，按钮为 Resume、Stop。Stop 保存计时但不完成任务。全局计时条按计划内容列居中，侧栏收起或调宽后仍居中。完成操作先由 Todofy 确认 Tasks 的结果，再结算对应 FlowDay 日期。

FlowDay 本地记录保持标题、估时和原应用入口，不创建任务的完成请求。旧日期的活动计时不冒充今天同名 ID 的活动计时，也不允许今天另启一段覆盖它。全局计时条在 Plan／Focus 切换时保留，不新增浏览器本地计时存储。

## 写入与读取

任务详情只为用户编辑过的规划范围、领域、截止日期和提前量保留局部草稿；其余字段随任务刷新。草稿对应字段在别处改变时，先提示“保留我的修改／使用最新值”，保存暂不可用；保留仅接受当前值作为新的比较基线，仍要再点保存。规划写入只提交改变的字段，截止日期写入沿用现有接口并保留最新未编辑提前量。估时与新增步骤沿用原流程。

2026-10-15 owner 批准：拖动先显示、按序保存，只对下列拖动与移出放宽“写入期间禁用写入控件”。

- Review 跨列拖动和列内排序、Week 拖入日期、“下一步”排序、跨日移动和同日排序落下后，卡片立即显示在预期位置。只有这张卡等待：变暗、小转圈、不可拖动，移出按钮隐藏。其他卡片、切周和下一次拖动照常可用。
- 等待确认的卡片在可访问名称中带“正在更新…”；抓手用 `aria-disabled` 停用但保持可聚焦，键盘落下后焦点留在移动的卡片上。减少动态效果时小转圈停止，只保留变暗。
- 等待确认的 Review 卡仍带拖动前的 etag：它的详情在确认或撤回前只读，详情标题显示同一等待标记；结束后显示服务端保留的规划范围。本周目标与任务无关，拖动期间照常可编辑。
- “移出日期”不提前删除：卡片原位等待，FlowDay 确认后才消失。
- 所有写入进入同一个先进先出队列，按操作顺序执行。FlowDay UpdateFlow 没有 etag、后写覆盖先写，所以移出日期和加入今天在执行时先 GetFlow 读取当前队列，只增删这一项，不写回屏幕上可能过时的队列；其他标签页刚加入的步骤和排在前面的移出都会保留。任务写入仍检查 etag。确认后换成服务端返回的任务或队列。
- 任一写入失败时，排在其后的写入不再发送，所有等待确认的预期变化撤回；原有错误区域说明“更改未保存，已恢复”、实际失败和其后未发送的更改数，队列空闲后重新读取。等待确认的卡片不显示为已保存。
- 邮件归类的保存只写 Todofy，在对话框里等待和报错。
- Week 的“添加步骤”（下一步托盘的一格输入）也先确认，但不打断打字：回车后标题先作为等待卡显示，输入框清空并保持打开，读取列出新步骤后换成步骤卡；一次只保存一个。
- 完成、在任务详情添加小步骤、估时、提前开始、标为进行中（含看板卡片的“开始”）、详情中的规划保存、添加或移除依赖、本周目标、加入今天、计时以及周回顾中的移到本月、留到下周和完成回顾仍先确认，写入期间停用写入控件；本周目标和“沿用”只用 `aria-disabled` 标为不可用，保留焦点（见[本周目标](#本周目标)）。
- 依赖的核对（ResolveDependencies）在 Review 看板显示的完整读取之后于后台进行，每次读取至多一次，不进写入队列、不停用控件；它失败时不显示错误，下次完整读取再问。与它重叠的写入确认后，它的回答不合并，由下一次读取显示。

读取不锁定看板，也不重复读取写入已返回的结果：

- 打开、刷新按钮、返回标签页（距上次完整读取至少 60 秒）和写入后需要的读取都在后台进行，只转动标题栏刷新图标。与写入重叠的读取作废，队列空闲后再读，旧读取不会覆盖较新的确认结果；两次读取重叠时，先发出的读取晚到也不覆盖后发出的结果。
- SetTaskPlan（含标为进行中）、SetTaskLead 的 PlanningTask、SetWeeklyBet 返回的目标和确认后的日期队列直接合并，不再读七天；目标别处改过时只重读一次 ReadPlan。
- 完成任务后仍重新读取，不在本地删除：Tasks 完成循环任务时会推进到下一次。读取完成前该步骤等待，不能再次完成。
- 离开 Plan／Focus 时，上次确认的数据只留在当前页面内存中；返回时立即显示，再后台读取。它可能早于一次完成或跨过午夜，所以本次读取完成前不开放写入；这次读取失败时只显示错误，并丢弃这份内存数据。离开时显示本周的，返回后跟随服务端的当前周（含周一轮换）。
- 加入日期和跨日移动不等 FlowDay 同步：FlowDay 的队列接受任何任务 ID，它的任务镜像由 FlowDay 自己的页面同步。估时就是 Tasks 的时长，由宿主写入（`updateEstimate`），FlowDay 只读镜像里的副本。

## 数据与接口边界

根 IDL 为 `proto/todofy/ui/v1/plus_service.proto`，FlowDay 的队列与计时 IDL 为 `proto/flowday/ui/v1/flowday_ui_service.proto`。修改 IDL 后使用根工具链生成客户端，应用不保存另一份协议。

| 用户操作             | 接口                                                                                             | 确认结果                                              |
| -------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| 加载                 | ReadPlan、完整 ListPlanningTasks、FlowDay ListTasks、七日 GetFlow、GetTimerSession               | 元数据、任务、所选周队列和真实今天计时                |
| 改规划范围／领域     | SetTaskPlan（不再接受退役的 `bet`，带它的请求 BAD_REQUEST 且不写入）                             | 当前 PlanningTask，合并单任务                         |
| 标为／取消进行中     | SetTaskPlan 的 `active`：只增删 `active` 标记                                                    | 当前 PlanningTask，合并单任务                         |
| 搁置／移出搁置       | SetTaskPlan 的 `parked`：加 `parked` 时去掉规划范围和 `active`                                   | 当前 PlanningTask，合并单任务                         |
| 调整列内顺序         | ReorderTasks：列的顺序存 Todofy；移动卡片的兄弟任务交换位置，等待中、搁置除外          | 保存的列顺序和这些任务新的位置，直接合并    |
| 保存、清空、沿用目标 | SetWeeklyBet：`{week_start, area, text, etag}`，只写 D1 `plan_notes`，不写任务              | 返回的 WeeklyBet 直接合并；冲突时重读一次 ReadPlan    |
| 创建小步骤           | AppendTaskSteps                                                                                  | 原父任务下新步骤的 ID（按输入顺序），后台再读取       |
| 同日队列             | UpdateFlow                                                                                       | 确认后的目标 FlowDayPlan，直接合并                    |
| 移出日期／加入今天   | GetFlow 读取当前队列，再 UpdateFlow 只增删一项                                                   | 确认后的该日 FlowDayPlan，直接合并                    |
| 跨日队列             | RolloverFlow，再 UpdateFlow 排列插入位置                                                         | 确认后的源／目标 FlowDayPlan，直接合并                |
| 估时                 | 宿主的 `updateEstimate`：Tasks UpdateTask 的 `duration_minutes`                                  | 零表示清空；FlowDay 的镜像随后同步                    |
| 计时                 | CommandTimer，etag 与稳定 request ID                                                             | TimerSession 映射为 TimerSnapshot；idle 清除显示状态  |
| 真正完成（Focus 与 Plan 的勾选框） | CompleteTask，再结算 FlowDay；日历卡片带所在日期                                 | Tasks 确认后后台重新读取，不靠本地删除                |
| 提前开始             | SetTaskLead                                                                                      | 确认后的 PlanningTask（Deadline、leadDays），Due 保留 |
| 周回顾数据           | ReadPlan 的待处理邮件数、回顾任务、下周选择 ID 和上周至下周的目标；ListPlanningTasks 的 update_time  | 与加载一同读取，不另发请求                            |
| 依赖                 | ReadPlan 的 `dependencies`（FULL）；PlanningTask 的 `recurring`、`completed_count`               | 只有 ID 与计数，与加载一同读取                        |
| 添加／移除依赖       | SetTaskDependency：只写 Todofy 的规划库，不写任务                                           | 这个任务确认后的依赖，直接合并                        |
| 核对依赖             | ResolveDependencies：Review 显示的完整读取后，最多 20 个待核对的 ID                              | 全部依赖和不再等待的任务（删除或说不出），直接合并    |
| 移到本月／留到下周   | SetTaskPlan（stage monthly／committed）                                                          | 当前 PlanningTask，合并单任务                         |
| 完成回顾             | CompleteTask，不带 flow_date                                                                     | Tasks 确认后后台重新读取                              |
| 邮件归类             | ReadMailSettings、UpdateMailCategories（整组替换，只写 D1，可为空）                              | 保存后的归类和 etag                                   |

初次读取并行获取独立数据；切周只读七天队列。App 合并确认的任务、队列和计时响应，原有读取序号保护正在查看的周，Plan／Focus 切换不扫描所有任务。离开 Plan／Focus 后返回时先显示内存中的上次确认数据，再后台重新读取；读取完成前不开放写入。宿主提供两个传输：Tasks 把 PlusService 发到同源的 `/api/plus/v1/*`，把 FlowDay 的方法发到 `/api/plus/flowday/*`；Todofy 的 Planning 通道只转发 Tasks 用到的方法。
