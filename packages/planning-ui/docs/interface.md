# 规划界面与接口说明

扩展已退役。本文件保留历史设计或验收；当前入口是 [Tasks](../../tasks/README.md)，原生功能验收见[对照表](../../tasks/docs/planning-parity.md)。Tasks 不需要扩展或连接口令。

## 使用目标

用户把较大的事项分成可执行的小步骤，每周决定承诺，再把步骤安排到某天。界面应减少移动标签、查看父任务和在多个应用间切换的劳动。具体做什么仍由用户选择。工作最多五项、生活最多三项是提示，不拒绝操作，也不代替周末回顾。

## Plan 的组成

Plan 顶部保留当前账户周的本周目标，下方有 Review 和 Week 两个视图。第一次打开默认 Review 和 All，工作／生活过滤不改变真实标签。浏览另一周只影响 Week 的日期队列，不把当前承诺或本周目标伪装成历史快照。

Review／Week、Review 的领域过滤、本周周回顾是否展开及勾选、Week 选中的承诺和“本周承诺”的折叠存在扩展的 storage.local（只有 ID 和行号，按字段合并写入），离开再回来、浏览器后退和刷新后恢复；断开连接时清除（2026-10-17 owner 决定）。Plan 挂载时读一次，之后只在用户改动时写入改动的字段，单纯打开不写入。记住的承诺已不在本周承诺里时选第一个，记住的领域不再出现在过滤里时显示全部；读不到时用默认值，存不进时页面照常工作。Week 自己的领域过滤不记住。同一字段在两个标签页里先后改动时以后改的为准。

### 本周目标

2026-10-16 owner 定稿：工作、生活各一行用户自己写的文字（最多 160 个 UTF-16 单位），原地编辑，存在 Todofy 的规划库（D1 `plan_notes`，kind `bets`，按账户周一和领域），从不写入 Todoist，与任何任务、承诺或标签都没有关联。旧的 `@bets` 任务不转换：现有的周一重置照旧去掉这个标签，`@bets` 标签和 🎯 Bets 筛选器原样保留（Plus 继续隐藏该筛选器）。

- 位置不变，在 Review／Week 上方；两列“工作／Work”“生活／Personal”，窄于 650px 时上下排列；只显示当前账户周，Week 翻到别的周不跟着变。
- 已写：目标文字本身就是编辑按钮（14px、600、可换行、纯文本、不识别链接），悬停时 `--plus-hover` 底色和文字光标，没有铅笔图标；按钮名 `编辑工作目标：{text}`／`Edit work goal: {text}`。
- 空：13px 灰字按钮“写下这周的工作目标”／“Write this week's work goal”（生活同理）。
- 空、上周有：下面多一行 12px 灰字“上周：{text}”，单行省略，完整内容在 `title`；悬停或焦点在这一列时旁边出现强调色的“沿用／Keep”，没有悬停的设备上一直显示；按钮名 `沿用上周的工作目标：{text}`。点一下把上周的文字写成本周的，焦点落在保存好的目标上。这是延续目标的唯一入口。
- 编辑中：原地换成同字号、同位置的一行输入框（`maxlength=160`），占位“这周最想推进的一件事”，标签“本周工作目标”，提示“回车保存 · Esc 取消”（输入框的 `aria-describedby`），剩 20 字以内时加“ · 还可输入 {n} 字”。计划页里提示放在这一列标题行的右端，整块高度不变，下面的看板不动；周回顾里仍在输入框下面一行。保存中输入框只读，末端显示 PendingMark“正在更新…”。
- 焦点框画在目标按钮内侧（`outline-offset: −1px`，同输入框），按 Enter、Esc 或“沿用”回到目标时不压到上面的列标题。
- 别处改过（ETAG_MISMATCH）：输入框下一行 `role=alert`“这条目标已在别处改过。再按回车会用你的文字替换它；按 Esc 查看最新内容。”，草稿保留，同时重读一次 ReadPlan 显示最新内容；之后只有 Enter 或 Esc 决定。
- 这一周已结束（ACTION_NOT_ALLOWED）：`role=alert`“这一周已经结束，没有保存。”，草稿留着，Enter 不再写入，Esc 关掉；随后后台重读新的一周。
- 保存失败：现有横幅“未确认保存成功，请重试。”，草稿留在输入框里。
- 未配置、断开或维护中：现有 fieldset 停用，横幅不变，目标文字照常可读。

什么时候保存（`src/BetText.tsx`）：

- 在目标上按 Enter 或 Space 打开编辑框，光标放在末尾。
- Enter 保存；输入法组字时的 Enter（`isComposing` 或 keyCode 229）不算，中文输入不会提前保存。文字没改时直接关掉，不写入。
- Tab 或点页面里别的地方：文字改过且不为空就保存，焦点不动。切换窗口、切到别的应用或标签页被隐藏（`document.hasFocus()` 为 false）不保存，草稿保持打开；Plus 被重新挂载时草稿丢弃，也不写入。
- 离开时框是空的不清空，恢复原来的文字；只有在空框里按 Enter 才清空这一周的目标（保留这一行，正文为空，rev 加 1）。
- Esc 取消，恢复原文，焦点回到目标；Plus 的 shadow root 隔离按键，不触发 Todoist 的快捷键。
- 按 Enter 或点“沿用”之后焦点落在保存好的目标上；因离开而保存时焦点不动。
- Tab 顺序：工作目标 →（沿用）→ 生活目标 →（沿用）。每列标题是 h3，整块的 aria-label 仍是“本周目标”。
- 结果由隐藏的 `role=status` 读出：“已保存工作目标”“已清空工作目标”“已沿用上周的工作目标”（生活同理）。这个区域一直在，只换文字（`src/announce.ts`）；同一句话连着出现两次时先清空、100ms 后再写，第二次也会被读出。
- 其他写入等待确认时，目标和“沿用”只用 `aria-disabled` 标为不可用（目标变暗、“沿用”变灰且仍只在悬停或焦点时出现，点击无效），不用 `disabled`：否则 Tab 刚移到另一行目标上的焦点会被它自己那次保存夺走。

写入是 SetWeeklyBet：只写 D1，不调用 Todoist、不做 metadata 同步，也没有回执；先比较，文字与已存相同就直接返回已存的目标（所以丢失回答后的重发、跨过周日午夜的重放都安全，请求不带 request ID），否则只接受本周和下周，再按 rev（etag）写入一条。返回的 WeeklyBet 直接合并进 `plan.weeklyBets`，不再读取。ReadPlan（FULL）在周回顾那一批 D1 查询里多一条，返回上周、本周和下周的目标，最多 6 行。

### Review

2026-10-16 owner 定稿，2026-10-17 加入“搁置”：从左到右是“该开始／Start now”、“等待中／Waiting”、“搁置／Parked”和四个规划列 Quarter、Month、Week、Committed（本季度、本月、本周、本周承诺）。前两列没有卡片时整列不渲染。“搁置”只在账户有名为 `parked` 的标签时存在；存在时和四个规划列一样始终显示，空时写“拖到这里搁置／Drop here to park”：接受投放的列若到拖动开始才出现，会把正在瞄准的列挤开。它空着、又独占规划列上方一整行时（五列、内容区窄于约 1,050px）只是一条细条：标题行加一行提示，约 70px 高，不再是 170px 的空列；和规划列同在一行时仍与它们同样大小。没有新标签页。规划列和“搁置”的标题同时显示它写入的当前 `@label`。Month、Week、Committed 使用明确绑定的标签；Quarter 可以不绑定，未绑定时不接受该范围的写入。五到七列在宽窗口排成一行。内容区窄于约 1,470px（七列）、1,260px（六列）或 1,050px（五列）时，四个规划列仍按顺序排成一行，侧边的列（该开始、等待中、搁置）在它上方并排（三列时各占三分之一，两列时各占一半，只有一列时占满整行），从它们拖入规划列是直接向下；窄于约 800px 时每行两列（该开始｜等待中、搁置｜空格、本季度｜本月、本周｜本周承诺：规划列总是另起一行），窄于约 430px 时一列。各列用同一种列和事项卡，样式相同。

每个任务只在一列出现，取第一条命中的规则（`src/review-lanes.ts`）：

0. 带字面标签 `parked`，且账户有这个标签：搁置，无论它有没有规划标签、在不在等或该不该开始。所以它也不在任何承诺列表里（Week 的总览、工具栏的数量、周回顾），不是 Week 的下一步，也不算“等待中”。
1. 有自己的规划标签（quarter／candiate／focus／committed）：留在该列。它在等或该开始时，卡片用一句安静的状态说明，见[截止日期](#截止日期)和[等待中](#等待中)。
2. `@waiting` 或 `@blocked`，或在等另一个尚未完成的任务（[依赖](#依赖)）：等待中。
3. 启动窗口已开或已过截止，且不是进行中：该开始。只因 7 天日期规则（Candidate If）成为 Week 待选的任务也进该开始，不进 Week。
4. 其余按原有日期规则留在 Week。

小步骤不是所属事项那一列的卡片，即使带着同一个规划标签，它也只是事项卡里的一步；所以在等或该开始的小步骤在“等待中”或“该开始”有自己的卡。投放有落点检查：按预测写入后，卡片必须在目标列里，否则这次投放不写入，卡片回到原处。所以把这样的卡（或搁置的小步骤）拖进所属事项的列不写入：写入后它会回到原列，或只是事项卡里的一步。只有从“该开始”拖入并标为进行中是确认，照常写入：它可以离开看板，只是不能回到“该开始”。拖入别的规划列（在那里成为自己的卡）照常写入。

事项卡按以下顺序阅读：标题、工作／生活上下文与步骤及排程数量；在等或该开始的卡片把步骤数量换成一句 12px muted 状态，“搁置”里的卡片换成“N 天未变动”（它在等时仍写在等；搁置的任务从不“该开始”）。“搁置”按最久未变动排在前，只先显示前 3 张（侧边的列在规划列上方时，一堆搁置的卡不会把规划列挤出屏幕），其余收在一行 12px 强调色的“再显示 N 项／N more”后面，展开后是“收起／Show fewer”，只是这次显示的状态。领域名总是完整显示：列窄时（七列一行时每列约 205px）步骤数量移到领域下方，仍靠右，卡片里的文字从不越出卡片边缘；状态只有一段时同样在领域右侧或其下方靠右；有两段（`12 天未变动 · 10月22日截止`）时在领域下方单独一行，太窄时在两段之间折行，行首、行尾都不留 `·`。拖动时浮起的卡片与原卡同宽同高（dnd-kit 按原卡设定浮层尺寸），也带抓手。Todoist 优先级保留其原值，用 14px 旗标和原有优先级颜色表示；静止卡片只用细边线，拖动浮层保留阴影。整体目标不再以每张承诺卡的星标呈现。标题点击打开任务详情；单独抓手拖动卡片。落在同一列的卡片上调整这一列的顺序（见下段），落在同一列的空白处无变化；跨规划列仅调用该任务的规划范围写入。从“该开始”拖入任一规划列就是确认：同一次 SetTaskPlan 写入该列的规划标签和 `active`（账户没有 `active` 标签时只写规划范围）。从“等待中”拖入只写规划范围，不去掉 `@waiting`／`@blocked`，也不加 `active`。拖入“搁置”只发 SetTaskPlan `{parked: true}`：加上 `@parked`，Todofy 同时去掉所有规划标签和 `active`（从“该开始”拖入也不标为进行中）；从“搁置”拖入规划列发 `{stage, parked: false}`，写入该列的标签并去掉 `@parked`；在任务详情（点搁置卡片的标题打开）里给它选一个规划范围后保存，或点“标为进行中”，同样带 `parked: false`，它随之离开“搁置”，只改领域时不带。“该开始”和“等待中”不接受投放，落在上面的卡片（包括来自“搁置”的）回到原处。拖动都先显示、按序保存，失败时撤回，见[写入与读取](#写入与读取)。卡片不通过标签移动整棵子树。

每一列都可拖动或用键盘调整顺序（2026-10-17 owner 决定）。只有落在同一列的卡片上才换位置：被拖的卡占据那张卡的位置（向上移时在它前面，向下移时在它后面），落在列的空白处、标题或缝隙里不变。拖到同列另一张卡上时，那张卡的上方或下方出现日历同样的 3px 强调色插入线，标出真正的落点；拖动期间页面不移动任何卡片，落下前看到的顺序就是数据的顺序。拖到别的列（接受投放的规划列或“搁置”）时那一列照旧着色。键盘：抓手上按空格或回车拿起，方向键移到那个方向的下一张卡或下一列，空格或回车放下，Esc 取消；落下后焦点留在被移动卡片的抓手上。读屏按页面语言读出卡片标题、列名和位置，例如“已拿起：订场地”“移到：本周承诺第 2 项”“已放下：订场地”，从不读出内部 ID。每个抓手（Review 的卡片，Week 的步骤、快速事项和日历里的步骤）的描述是同一句操作说明“按空格或回车拿起，方向键移动，空格或回车放下，Esc 取消。”，角色说明是“可拖动／draggable”：说明放在 Plus 自己的 shadow root 里（隐藏，只作描述），因为 dnd-kit 放在 document.body 的那一句不能被 shadow root 里的 ID 引用。切换页面语言时拖动区重新挂载，说明和播报都换成新的语言。

顺序存在 Todofy 的规划库（`plan_settings` 的 `board`）。每列先按存好的顺序（已不在这一列的 ID 跳过），其余的按这一列原来的顺序排在后面；“该开始”相反，其余的排在前面，新到期的任务是最要紧的消息。原来的顺序：该开始按截止日期和优先级，等待中和搁置按最久未变动，规划列按事项顺序。跨列投放只写规划范围，卡片排在新列已排好的卡片之后（“该开始”是之前），除非新列存好的顺序里还留着它以前的位置。每列最多存 100 个：移到第 100 个之后的投放不保存。该开始和四个规划列同步到 Todoist：被移动卡片在这一列里的同一项目、分区和父任务下的兄弟任务按列中顺序交换原有的 `child_order`（`item_reorder`），其他任务不动，这一列里只有它自己时 Todoist 不变；等待中和搁置只存在 Todofy（它们按“未变动天数”排序，不写 Todoist）。每次投放一次 ReorderTasks，先显示、按序保存，失败时撤回。Week 的承诺总览与“本周承诺”一列同序。

“计划标签”选择当前已存在的 Todoist 标签，不能输入一个不存在的标签名。每列选择不同 ID，保存检查元数据 etag。更改映射影响后续投影和操作，不搬动已有任务。设置面板点击外部、Close 或 Escape 关闭。连接管理仍回到已有 owner 页面。

### Week

上方紧凑总览显示当前 Committed 事项，与 Review 的“本周承诺”一列是同一组、同一顺序（搁置的不在其中）。默认展示全部，工作／生活过滤保持可选。点击一个事项展开它的小步骤，再从步骤托盘拖入日期。没有独立规划标签的中间层级和仅因日期进入候选的子步骤继续属于父事项；显式使用不同范围标签的子事项按自身范围处理。日期与真实标签不重写。

步骤卡先显示标题，下方显示短所属事项和估时；父事项与步骤共用由事项 ID 派生的色标。事项卡标题最多两行，完整名称可在详情查看。步骤卡按内容排布，不按估时把普通卡片拉成占满屏幕的长块。实际数据没有额外保存色彩设置或像素布局。

“下一步”按 Todoist 的子任务顺序列出（2026-10-17 owner 决定）：逐层深入，每个父任务的子任务在每组都有 `order_key` 时按它（逐字节比较），否则按 `child_order`，没有位置的排在最后。同一父任务下的步骤可拖动或用键盘调整顺序：拖到兄弟步骤上时，三列托盘里那张卡的左边（往前移）或右边（往后移）、单列托盘里它的上方或下方出现 3px 强调色的线，落下后占据它的位置；落在别的父任务的步骤、“添加步骤”或等待卡上不写入，拖到日期照常安排。一次 ReorderTasks 把这个父任务的全部子任务（包括有自己步骤的）按新顺序交换原有的 `child_order`（`item_reorder`），只改 Todoist 的顺序，不存列的顺序；位置缺失或重复时，或子任务超过一次请求能带的 100 个时不写入。落下后先显示，步骤变暗等待，失败时撤回。键盘：抓手上空格或回车拿起，方向键在兄弟步骤和日期之间逐个移动，空格或回车放下，Esc 取消；落下后焦点留在它的抓手上。

日期队列保留原始顺序、本地任务、杂项与已完成 ID。托盘拖动给目标日增加安排，同一小步骤可以安排在多日；拖动日历中已有卡片才从原日移到目标日。投放到卡片前表示插入到它前面；投放到列底部表示追加；同日抓手调整顺序。跨日移动先确认源／目标队列，再在目标位置插入。落下后卡片立即显示在新位置并等待确认，见[写入与读取](#写入与读取)。已运行或暂停的步骤需要先停止计时。

日历显示上一周、下一周、回本周。日历内容区大于 960px 时显示七日（常见 1440px 桌面窗口），420–960px 显示三日，更窄时显示单日；三日和单日布局的上方日期按钮仍可选日和投放。显示其他周不修改任务 Due 或 Deadline。日期队列变更不修改规划列。

承诺总览标题行内有一段安静的文字“N 项承诺这 7 天还没有安排”：承诺本身和它未完成的步骤都不在所显示 7 天的队列中。只在 N 大于 0 时出现，没有逐卡标记；点击依次选中下一个这样的承诺，展开其步骤托盘，按钮提示“选中下一个”。它只提示，不自动安排。

“本周承诺”标题本身是折叠按钮（2026-10-17 owner 决定），默认展开，折叠与否和选中的事项都会记住（见[Plan 的组成](#plan-的组成)）。样式同 Todoist 分区的折叠：16px 的 Lucide 箭头在标题左侧的留白里，标题仍与下面的卡片左缘对齐；箭头展开时只在悬停标题行或键盘焦点时出现，折叠时一直显示；按钮保持标题的 15px、600，悬停时 `--plus-hover` 底色。折叠和展开时标题行不移动（看不见的领域过滤仍占着位置）。折叠后只留标题行“本周承诺 6 项”（不重复选中事项的标题，下面托盘的标题就是它）、那行未安排提示和“下一步”托盘；没有选中事项时托盘位置写“展开“本周承诺”，选择一个事项。”。领域过滤和事项网格折叠时仍在页面里（`hidden`），所以按钮的 `aria-controls` 始终指向网格。“周回顾”的“去安排”会展开它。

“下一步”托盘的最后一格是“添加步骤／Add steps”（2026-10-17 owner 决定）：样式同 Todoist 自己的“添加任务”行，32px 高、14px 灰字，前面是强调色的 16px 加号，悬停或键盘焦点时文字变成强调色；可访问名称“为「{承诺}」添加步骤”。三列托盘里它占一格，窄托盘（≤680px）里占一整行。承诺的子任务都有自己的规划标签、托盘里没有步骤时，“先写下一步，剩下的可以以后再想。”那行在网格上方，网格里只有这一格。

- 点一下，原地换成同样 32px 高、占满这一格的单行输入框（14px，最多 500 字），自动获得焦点；占位“步骤名称，回车添加”，标签“新步骤”，读屏另外读出“回车添加，Esc 关闭”。打开和关闭都不改变这一行的高度。
- 回车把文字作为选中承诺的子任务写进 Todoist（AppendTaskSteps，先确认）。输入框立即清空，保持打开和焦点，可以接着输入下一个；标题先作为一张变暗的等待卡排在这一格前面（PendingMark 在抓手的位置，没有抓手；标题下一行是灰色的“正在更新…”，与步骤卡的估时行同高，读屏只读标记），直到读取列出新步骤，再换成普通的步骤卡（Todoist 把它排在同级最后），这一行的高度和输入框的位置都不变。托盘里的 `role=status` 读出“已添加步骤：{标题}”。承诺原来没有子任务时，它自己就不再是那一个步骤。
- 一次只保存一个：保存中，或有其他写入在等时，回车不写入，输入框标为 `aria-disabled`，但照常可以打字。输入法组字时的回车不算。
- Esc 关闭并丢弃草稿，焦点回到“添加步骤”；空着回车也关闭并回到它；空着离开时关闭，焦点不动；留有文字时离开不写入，草稿和输入框都留着。
- 失败时现有横幅说明，等待卡消失。输入框是空的，失败的标题就回到框里，再按回车用同一个请求 ID 重试（回执规则）；改过的标题是新的请求。已经输入了新草稿时保留新草稿，失败的标题不再放回。
- 改选另一个承诺（点卡片、那行未安排提示或领域过滤）会关闭输入框并丢弃草稿，所以草稿不会写到别的承诺下；切到 Review 也会关闭它。读取后选中的承诺不再是本周承诺（在别处完成、改了规划范围或搁置），Week 改选第一个承诺时，输入框同样关闭，焦点不动：打开的输入框只属于打开它的那个承诺。它不记住。周回顾的“去安排”切到 Week，选中第一个未安排的承诺，打开它的输入框。

“下一步”托盘下面是一行安静的“快速事项／Quick tasks”（2026-10-17 owner 决定），承接原生的 Quick / Ops 筛选器（`@quick & (no date | 3 days)`）：带字面标签 `quick`，并且没有到期日，或到期日、截止日期最晚在后天（含已过期；带固定时区的到期时间按账户时区的日期算）。已排在所显示 7 天里的、上面托盘里已有的步骤和搁置的任务不在这里。行首是 12px 灰字“快速事项 N”，后面是 28px 高的单行小卡：与步骤卡同样的底色和边线，抓手加 12px 标题，最宽 200px，超出以省略号结尾，完整标题在 `title` 里，点标题打开任务详情。有到期日的按日期在前，没有的在后，同组里优先级高的在前；只先显示 6 张，其余收在“再显示 N 项”后面。小卡和步骤一样拖进某天（加入该日的 FlowDay 队列），排好后离开这一行；没有可显示的任务时整行不出现。

### 截止日期

2026-10-16 owner 定稿，取代同日第一版的“截止日期 · N”列表（设计 §1、§3）。截止日期按一条生命周期看：截止日期 → 启动窗口 → 进行中 → 完成。任务有 Todoist 原生截止日期和提前量标签（`lead_1d`、`lead_3d`、`lead_1w`、`lead_2w`、`lead_1m`）；从截止日期前 N 天起（Todofy 原有的 `must_start` 规则，已过截止也算）它出现在看板上，在此之前不出现。确认后它带上 `@active`，不再显示为该开始。没有新页面、新语法或新图标；唯一的颜色是“已过 N 天”的 `--plus-danger`。

`src/deadlines.ts` 在完整读取之后，按 Todofy 一字未改的 `must_start`、`missing_lead` 和字面标签 `active`、`blocked`、`parked`，给每个有截止日期、且不是 `@parked` 的任务一个状态，取第一条命中的规则：

| #   | 条件                                | 状态         | 出现在                                         |
| --- | ----------------------------------- | ------------ | ---------------------------------------------- |
| 1   | 字面标签 `active`，且没有 `blocked` | 进行中       | 不占看板的列；任务详情写 `进行中 · 还剩 12 天` |
| 2   | `must_start`，截止日期早于今天      | 已过截止     | 该开始，或它自己的规划列                       |
| 3   | `must_start`                        | 已到启动窗口 | 同上                                           |
| 4   | `missing_lead`                      | 未设提前量   | 只在周回顾的一行，见[周回顾](#周回顾)          |
| 5   | 其余（窗口未到）                    | —            | 不出现，只在任务详情说明                       |

`@waiting`／`@blocked` 和尚未满足的[依赖](#依赖)在列的规则中优先：已过截止的 `@waiting` 任务（`must_start` 包含它）在“等待中”，在等另一个任务、启动窗口已开的任务也在“等待中”，不在“该开始”。

“该开始”按截止日期从早到晚，同一天按优先级。卡片是标题、领域和一句状态：`还剩 5 天`、`明天截止`、`今天截止` 或 `已过 2 天`（danger）；英文为 `5 days left`、`Deadline tomorrow`、`Deadline today`、`2 days late`。有规划标签的卡在自己的列写同一句。完整日期是状态的 `title`（`截止日期：10月11日周日`）；读屏只补上状态没说的部分：状态已写日期时只加星期（`11月30日截止，周一`），否则加完整日期（`已过 2 天，10月11日周日`）。

确认有两种：把卡片从“该开始”拖入某个规划列（规划标签和 `active` 一次写入，见 [Review](#review)），或用卡片的悬停操作“开始／Start”，只加 `active`。“开始”平时不占位置，标题用满卡片宽度；只在鼠标悬停或键盘焦点（`:focus-visible`）进入该卡时出现在标题第一行的右端，标题在它下面淡入卡片自己的底色，和 Todoist 自己的任务行一样。它只用透明度隐藏，不挪动标题和状态，仍在 Tab 顺序（卡片之后）和可访问树里，可访问名称为“开始：标题”；不能用时（写入期间、拖动未确认）停用并保持隐藏。没有悬停能力的设备一直显示，盖住标题第一行的末端。有规划标签、在启动窗口里的卡也有“开始”。它只在账户已有字面标签 `active` 时出现，是先确认的 SetTaskPlan `{active: true}` 写入：确认后合并返回的任务，不再整表读取；“该开始”里的卡离开看板（该列空了就整列消失），有规划标签的卡留在原列、状态消失。焦点移到下一张卡的“开始”，没有了就回到该卡或看板第一张卡；看板旁的 `role="status"` 读出“已标为进行中：标题”。事项卡的拖动尚未确认时，它还带着拖动前的 etag，所以“开始”先停用。

已过截止或已到启动窗口的任务本身和它未完成的小步骤都不在本周已读取的 7 天队列里时，Focus 摘要下方有一行安静文字，见[Focus 与计时](#focus-与计时)。Week 的承诺总览用同一张事项卡，但始终显示步骤和排程数量，不写在等或该开始的状态：那里是安排步骤的地方。不把启动窗口里的任务投进 Week 列。

有截止日期但没有提前量标签的任务只在周回顾出现一行“N 项截止还没设提前量”；展开后每项可直接用任务详情的同一个提前量下拉框选择，看板和其他地方都不显示。已过截止、又没设提前量的任务按规则 2 也在“该开始”。

### 任务详情的截止日期

Plan 编辑器和原生“步骤与时间”共用同一段。原来的“启动窗口：日期”换成一句按当前输入框计算的状态（12px muted，只有已过截止用 danger）：窗口未到时 `启动窗口: 10月24日周六`，窗口已开 `已到启动窗口 · 还剩 5 天`，已过截止 `已过截止 2 天`，进行中 `进行中 · 还剩 12 天`；未设提前开始时不加字，下拉框已显示“未设置”。“保存”后面有 32px 次要按钮“标为进行中”，任务已是 `@active` 时为“取消进行中／Not in progress”；只在任务有截止日期、且账户有 `active` 标签时出现，每次点击是一次写入，写入期间停用，结果由该段的 `role="status"` 读出；窄编辑器里按钮文字不换行，日期框和下拉框收窄。这句状态只说日期和进行中标签，不看 `@waiting`、`@blocked`：在等的任务进入窗口后也写“已到启动窗口”，它在哪一列由 [Review](#review) 的规则决定。下拉框的英文单数写作 `1 day`。详情里的按钮叫“标为进行中”；看板卡片上同一写入按 owner 定稿叫“开始”，可访问名称带任务标题，与 Focus 计时器的 Start 区分。

### 等待中

“等待中”是 Review 的第二列，紧挨“该开始”右侧，只在有不带自己规划标签的 `@waiting`、`@blocked` 或在等另一个任务的任务时出现（搁置的任务在“搁置”，不在这里，周回顾的计数同样不算它们）；有规划标签的在等任务留在自己的列，卡片写同一句状态。在等另一个任务时，“N 天未变动”换成 `等「订场地」`（多个时 `等 2 项`；英文 `Waiting for “Book venue”`、`Waiting for 2 tasks`），截止日期那一段照旧，见[依赖](#依赖)。卡片按 Todoist 的最后修改时间排列，最久未变动的在前，状态为“12 天未变动”（按满 24 小时计，不足一天为“1 天内有变动”；英文 `No change in 12 days`、`Changed within a day`）；有截止日期时加 `· 10月22日截止`（英文 `· Deadline Oct 22`），已过截止加 `· 已过 2 天`（danger，与“该开始”同一句，看板上只有这一种红字），两段时在领域下方单独一行。由此承接原来按截止日期列出等待任务的筛选器。任何 Todoist 编辑都会重置这个时间，所以它不表示已等待多久，也不推断在等谁。

卡片没有悬停操作：点击标题打开任务详情（那里仍可添加步骤、加入今天和在 Todoist 打开），拖入规划列只写规划范围。它不移除标签、不联系任何人，也没有新的存储。标签按后端 Must Start 已使用的字面名称识别，不创建标签。

### 依赖

2026-10-16 owner 定稿（设计 plus-next §2，数据层 §5.1）：一个任务可以等其他任务完成。依赖只存在 Todofy 的规划库里，是两个 Todofy 任务 ID 之间的一条边；不写进 Todoist 的标题、描述、评论或标签，也不镜像 `@blocked`，所以 Todoist 手机端和没装扩展的 Todoist 看不到它。它只影响显示：所等的任务完成后，这个任务显示为可以开始，不改日期、不加减标签。旧标题后缀 `<k:… dep:…>` 只在 Plus 的视图里隐藏，`dag_*` 标签一律忽略。

规则（`src/dependencies.ts`，完整读取之后）：

- 所等的任务 B 在活动列表里就在等；B 不在活动列表里就算满足（“消失即满足”），无论它是完成还是删除，Todofy 随后核对是哪一种。被重新打开的 B 又出现在列表里时重新算在等。
- 循环任务完成时只推进日期、ID 不变：Todoist 的 `completed_count` 在每次完成时加一、撤销时减一。建立依赖时 Todofy 记下 B 当时的计数，B 在那之后的下一次完成（计数大于记下的值）就算满足，以后的循环不再挡住 A；要等 B 的再下一次，就在选择框里再选一次 B，Todofy 从当时的计数重新记起。Todoist 不给出计数的循环任务不能被选作依赖。
- 只有仍在等的依赖算数：每个任务最多等 5 项，全部最多 300 条；不能等自己，也不能互相等待（含经过其他任务的环）。已满足的依赖不构成环，也不占 5 项：任务已有 5 条（或全部已有 300 条）时，它最早一条已满足的依赖给新的让位。选择时就不让选，Todofy 在锁内用一次 Todoist 读取判断哪些依赖仍在等，再查一次。

**任务详情的“依赖 / Depends on”段**：Plan 编辑器和原生“步骤与时间”共用，位于“截止日期”段之后，标题样式与“下一步”“截止日期”相同。

- 每个尚未满足的依赖一行：13px 标题按钮（在 Plan 中打开它的编辑器，在原生页面打开它的 Todoist 页面），循环任务右侧写 `下一次完成后 / After its next completion`；最右是 24px 的 ×，可访问名称 `移除依赖：订场地`，平时透明度为 0，只在悬停或键盘焦点进入这一行时出现，没有悬停能力的设备一直显示。
- 已满足的不逐条列出：全部满足时写 `所等的任务都已完成，可以开始了 / Everything it waits for is done — ready to start`，部分满足时 `另有 1 项已完成 / 1 more is done`。这一行右端同样有 24px 的 ×（`移除已完成的依赖 / Remove the done dependencies`），只在悬停或键盘焦点时出现，一次排队写入移除这些已满足的依赖，读出 `已移除已完成的依赖`。不移除时，它们在这个任务离开活动列表后由 Todofy 删除，或给新依赖让位；循环任务一直在列表里，所以这一行会留到移除或被新依赖替换为止。
- 有任务在等它时多一行只读文字：`「发邀请函」在等它`，多个时 `「发邀请函」等 2 项在等它`。
- `+ 添加依赖 / Add a dependency` 是 `.plus-text-button`；已有 5 项仍在等时停用，`title` 为 `最多 5 项 / Up to 5`。
- 行高 32px（含下边线），带 × 的已保存行和带等待标记的待确认行一样高，确认时不跳动。标题按钮平时像普通文字，悬停或键盘焦点时加下划线，表示点它会打开那个任务。

输入法组字期间，Enter、方向键和 Escape 交由输入法处理，不移动选项或添加依赖。选择框是内联的，不在 Todoist 弹窗或 Plan 的对话框里再套一层：32px 输入框自动获得焦点，占位文字 `搜索任务或父任务 / Search tasks or parents`；输入后在已完整读取的活动任务中按标题或父任务即时搜索，规则与原“更换目标”相同，没有语法；没有输入时不列出任何任务。结果最多 6 行，每行至少 28px：标题 13px，右侧是父任务路径（12px muted）。不列出任务自己、它的父任务和它的步骤，以及它仍在等的任务；已满足的循环任务会再列出，选它就等它的下一次完成。会形成循环的任务（按仍在等的依赖）仍列出但为灰色，右侧写 `会互相等待 / Would wait on each other`；没有计数的循环任务同样灰色，写 `重复任务不会结束 / Repeats, never finishes`；灰色的行不能选择，也从不高亮：高亮从第一个能选的行开始，↑↓ 只在能选的行之间移动，鼠标移到灰色行上不改变高亮，Enter 添加高亮的那一行；Escape 或 `取消 / Cancel` 收起选择框，Escape 不再传给外面的对话框或 Todoist 弹窗，焦点回到“添加依赖”。

选中即写入，是先确认的 SetTaskDependency：新行先带现有的等待标记（PendingMark）显示，写入期间停用写入控件，确认后合并返回的这个任务的依赖，不再整表读取；编辑器的 `role="status"` 读出 `已添加依赖：订场地`。点 × 同样是一次写入，读出 `已移除依赖：订场地`。失败时用原有错误区域：Todofy 拒绝时写 `Not added: this dependency cannot be added now. Refresh and try again.`（别的标签页刚改过依赖、Plus 未启用、Todoist 暂停或被阻断都是同一个拒绝，所以不猜原因；和其他 API 错误一样只有英文），任务已不在活动列表时写 `Not added: one of these tasks is no longer active. Refresh and try again.`。

**看板与其他位置**：只因依赖而在等、又没有自己规划标签的任务在“等待中”，排序规则不变（最久未变动的在前）；有自己规划标签的留在原列。卡片计数那一段换成一句安静的状态 `等「订场地」`／`等 2 项`，有截止日期时后面照旧加截止日期那一段，可访问名称带同一句和完整标题；在等的卡片没有“开始”。所等任务的标题最宽 7em（中文约 7 个字），太长时在引号里以省略号结尾，引号保留，悬停提示完整标题；这一段永远只占一行，卡片窄时标题先缩短，两段的状态仍可在两段之间换行，不会溢出卡片。Focus 的那一行和周回顾的“等待中”计数都包含这类任务；Week 的承诺总览照旧只显示步骤和排程数。

**核对**：只有 Plan 的 Review 看板显示核对的提示，所以只有它核对：它每显示一次新的完整读取，若有依赖提到、但这次读取里没有的任务（先是等待方，再是还没确认完成的被等任务），或记为已完成、却又出现在读取里的被等任务（被重新打开），就在后台调用一次 ResolveDependencies，最多 20 个 ID；同一次页面访问里每个 ID 只问一次，已问过的不占名额，其余的在下次完整读取时轮到；失败的在下次完整读取时再问。Focus、Week 和原生页面从不调用，所以一次性的提示不会在看不到的地方用掉。Todofy 先向 Todoist 确认哪些在活动列表里：被重新打开的重新记为未关闭；消失的等待方删除它的依赖；被等任务按 Todoist 的活动记录记为完成，删除时删掉等它的依赖；活动记录说不出（没有完成或删除的记录，例如归档项目里的任务，或账户没有活动记录）时不作任何记录，同样删掉等它的依赖。提示在本次页面访问内出现一次，位于看板各列下方（不在上方，出现时看板不移动），12px muted：删除时 `「整理书架」等的任务已被删除，不再等待。`／`“Tidy the bookshelf” no longer waits — the task it waited for was deleted.`，说不出时 `「整理书架」等的任务已不在待办中，不再等待。`／`“Tidy the bookshelf” no longer waits — the task it waited for is no longer active.`；即使“等待中”已经没有任务也显示，由 `role="status"` 读出；刷新页面后不再出现，没有确认或按钮。

原生任务弹窗里折叠的“步骤与时间”按钮后缀（设计 plus-next §4 的 `planMarks`）和原生任务行标记都不在这一版。

### 周日选择留到下周

在账户时区的周日，用 Plus 把事项设为本周承诺，Todofy 把它记为下周的选择，周一 00:00 的重置会保留它的承诺标记；再下一个周一按普通承诺处理。只有 Plus 中的写入算数，周日在原生 Todoist 加的承诺照常重置。本周更早做出的承诺照常在周一重置。目标是文字，按周保存，从不被重置。

周日清单第 5 行标题是“下周承诺与目标／Next week's commitments and goals”，说明：“在 Plus 中周日选的承诺会留到下周，其余的周一照常重置。目标按周保存，不会被清除。”

- 展开按钮“选要留到下周的承诺（{n}）”只列承诺；周日想保留一个已在本周承诺中的事项，点“留到下周”：它再发送一次同样的承诺写入，规划范围不变时 Todofy 不改任何标签，季度等其他范围标签都保留。看板中周日拖入本周承诺，确认后清单立即显示为“已留到下周”，不再提供重复写入；已留下的事项之后在周日被移除承诺，就不再留到下周。
- 下面固定两行（`.weekly-review-items` 的样式）：先是灰色的“工作”“生活”，再是下周目标，编辑方式同上；空时“写下周的工作目标”，输入框标签“下周工作目标”，按钮名“编辑下周工作目标：{text}”。这里不放“沿用本周”：沿用只有一个入口，就是周一起空着的本周目标旁的“上周：… · 沿用”。

任务详情只发送用户改动的字段，周日只改领域不会把承诺误留到下周。仍带 `@bets` 的旧任务（只要设置里还有退役的 bets 绑定）在周一重置时照旧被去掉这个标签；周日承诺这样一个任务时，它的两个标记都会再留一周。后端规则见 [Todofy 文档](../../todofy/docs/todoist-plus.md#weekly-rollover-and-controls)。

## Focus 与计时

Focus 显示真实今天的未完成 FlowDay 队列，顺序与 Week 相同。卡片标题在上方，短所属事项、估时和计时信息在下方。空队列只有“调整计划”入口，不出现另一套任务挑选器。

摘要下方可能有一行安静文字（样式同 Week 的承诺提示，12px muted，悬停时强调色加下划线，没有图标），例如“1 项已过截止、2 项已到启动窗口，这周还没有安排”／“1 past deadline and 2 in their start window, not planned this week”。只有“已过截止”或“已到启动窗口”、又不带 `@waiting`／`@blocked`、也不在等另一个任务的任务（与看板一致：已过截止的在等任务在“等待中”）本身和它未完成的小步骤都不在本周已读取的 7 天队列里时才出现，每个任务只数一次，有自己规划标签、在原列写明状态的也算，所以数目可能多于“该开始”一列的卡片；Plan 正在看别的周时只看今天的队列；队列为空时也显示。点击打开 Plan › Review（全部领域），焦点放在“该开始”一列上；该列为空时（该开始的任务都有自己的规划标签）放在第一张该开始的卡上。按钮提示“在计划中查看”。它只提示，不往队列里加任何东西。

每个 Todoist 步骤显示独立的完成控件和 Start 按钮。完成控件是 Todoist 的优先级圆圈（P1 红、P2 橙、P3 蓝带浅色底，P4 灰），与 Review 卡片一致；没有完成控件的 FlowDay 记录保留同宽空位，标题对齐。运行后显示确认的经过时间及 Pause、Stop；暂停后状态写“已暂停／Paused”，按钮为 Resume、Stop。Stop 保存计时但不完成任务。全局计时条按 Plus 内容列居中，侧栏收起或调宽后仍居中。完成操作先由 Todofy 确认 Todoist 结果，再结算对应 FlowDay 日期。

FlowDay 本地记录保持标题、估时和原应用入口，不创建 Todoist 完成请求。旧日期的活动计时不冒充今天同名 ID 的活动计时，也不允许今天另启一段覆盖它。全局计时条在 Plan／Focus 切换时保留，不新增浏览器本地计时存储。

- 其他状态：读取中“正在读取邮件…”；没有邮件“邮件都处理完了”（下面可能仍有“其他任务”一行）；Todofy 没设邮件项目“Todofy 没有设置邮件项目”；读不到邮件时现有错误块“暂时读不到邮件。”，带刷新和连接设置，不显示列表；记住的快照或维护中照现有规则停用写入。

**全部删除**（现有 `.plus-dialog` 模态框）：标题“删除 {n} 封邮件？”，正文“Todoist 中这 {n} 个任务会被永久删除，无法撤销。”；有保留时再一行“有改动或已排进计划的 {k} 封会保留：{标题1}、{标题2}。”（最多列 3 个，再多写“等 {k} 封”）；超过 200 封时“一次最多 200 封：先删最早的 200 封，其余留在列表里。”。按钮“取消”（默认焦点，Esc 也是取消）和“删除 {n} 封”，都是普通的 `.plus-button`，不用红色。对话框的 `aria-describedby` 指向正文、保留说明和上限说明，读屏和标题一起读出“永久删除，无法撤销”。

- 范围在打开确认框那一刻冻结：屏幕上的行按 ID，去掉“动过的”（`src/mail.ts` 的 `touched`）：有标签、优先级不是 P4、有日期／截止日期／预估、有步骤、有依赖（在等别的任务或有任务在等它，已完成的也算）、在已读取的某个 FlowDay 日队列里、是正在计时的任务，或还有写入没完成。之后新到的邮件不在其中。
- 点“删除 {n} 封”和每次“重试”之前，按当时的数据再查一遍（`recheckedBatch`）：FlowDay 预估、日队列、计时和未完成的写入只有扩展看得到，对话框开着时别的标签页可能改了它们，返回标签页后的重新读取会带来。动过的移出范围、记入保留，只减不增；已不在列表里的任务留在范围里，交给 Todofy。数量变了就先不发送：标题、正文和按钮换成新的数字，对话框里隐藏的 `role=status` 读出新标题，用户再点一次才以新的请求 ID 发送（Todofy 按请求 ID 核对任务列表）。全都动过了就关闭对话框，状态行写“已删除 0 封；{b} 封有改动，已保留”。
- Todofy 在全新读取上再查一遍 Todoist 字段、评论数、依赖边和自己还没完成的写入（回执），查出动过的照样保留；重试时它再读一次冻结的任务，只删仍未动过的，不会新增，也不会删两次。列出的任务已经不在了（在 Todoist 里删了，或上一次删除成功但回应丢了、对话框又被关掉），算作已删除，这一行离开列表。
- 删除中按钮写“正在删除…”，两个按钮停用，相关行变淡，Esc 不关闭。完成后对话框关闭，这些行离开，状态行写“已删除 {n} 封邮件”，服务器保留了一部分时写“已删除 {a} 封；{b} 封有改动，已保留”。未能确认时对话框留着，写“未确认删除完成。重试会接着删完剩下的，不会重复删除。”，按钮变成“重试”，范围没变时沿用同一个请求 ID。删掉的邮件在 Todofy 里的总结一起删除（台账只留 ID 和状态）：这是 owner 删除邮件的唯一方式，在 Todoist 里直接删的任务总结仍在。

**邮件归类**（只由页头的齿轮打开，版式同“计划标签”对话框；点外侧、关闭按钮或 Esc 可关闭，焦点回到齿轮）：归类可有可无，一个也没有时也能保存。说明“每个归类是一个现有 Todoist 标签加一个优先级。归入时任务带上它们，并移到 Todoist 收件箱。”，读取中写“正在读取归类…”。每行一个标签下拉框（先是“工作”“生活”两个领域标签，再是其他现有标签；不列计划阶段标签、已退役的 bets、`lead_*` 和 `active`）、一个 P1–P4 下拉框和删除 ×（“删除归类：工作 · P2”）；归类名自动生成“{标签} · P{n}”。“添加归类”满 4 个时停用（`title` 为“最多 4 个”）。不再选去处：以前保存的去处 Todofy 留着，但不再使用。错误：“已有相同的归类。”“这个标签已不存在，请重新选择。”“为每个归类选一个标签。”保存只写 Todofy（UpdateMailSettings）；成功后对话框关闭（同“计划标签”），状态行写“已保存邮件归类”。关闭后焦点总是回到齿轮。保存失败时对话框留着，写出原因。

**收藏里的邮件项目**：PlanConfig 多一组只含 ID 的 `hiddenProjectIds`（`[inboxProjectId]`），断开连接时随配置清除；旧缓存没有这一项时按空处理。邮件项目的收藏行在 Plus 已挂载且已配置时，在所有 Todoist 页面都隐藏（2026-10-17 owner 决定，取代只在 Plus 页隐藏）；停用扩展或卸下时立即恢复，无需刷新。“我的项目”里照常显示，手机上不变。其他收藏的项目既不隐藏，也不折进 Other views。收藏列表靠第一个筛选器或标签收藏定位，收藏里只有项目时不整理。

插入位置有两种规则，各自固定：日期队列落在卡片上表示插到它前面；Review 的各列（以及 Week 的“下一步”）是列表移动，向上移时落在目标卡前面，向下移时落在它后面。两处都用同一条 3px 强调色插入线标出真正的落点。

Plus 只按已知真实对象 ID 隐藏被替代项。收藏项目保留（Todofy 的邮件项目除外：Plus 已挂载且已配置时在所有 Todoist 页面隐藏，停用扩展或卸下时立即恢复，见[邮件](#邮件)），其他标签和筛选器收在 Other views。Todofy 按精确的规范化查询认定被替代的筛选器；2026-10-16 起另有三个查询：`!nodeadline&(@blocked)&!@parked`（含不带括号的写法）、`@blocked` 和 `@active&!nodeadline&!@blocked&!@parked`，前两个由“等待中”（或在等任务自己的规划列）承接，第三个选出的是已确认进行中的任务，它们不再需要一列。Todofy 的一致性测试按原查询重建合成任务集合，断言每个任务都在看板上（“该开始”、“等待中”，或在自己的规划列并写明状态）或已是进行中，没设提前量的查询则断言每个任务都在周回顾那一行；不通过就不隐藏。扩展的同名测试按 API 字段检查看板的列。2026-10-17 起 Quick（`@quick&(nodate|3days)`）和 `@parked` 的筛选器也按精确查询隐藏（`@parked` 只在账户有 `parked` 标签时），分别由 Week 的“快速事项”和 Review 的“搁置”承接；Todofy 的一致性测试同样断言它们选出的每个任务都在这两处，扩展的同名测试按 API 字段检查。Other views 没有其他收藏时整组不显示。Other views 的展开或收起存在 storage.local 的一个布尔值里，刷新后保持，断开或更换连接时清除。停用或重新加载扩展后，回到已打开的 Todoist 标签页即恢复原控件，见[恢复](#恢复)；不删除 Todoist 筛选器、标签或收藏。

### 主题

2026-10-15 owner 批准。Todoist 把主题写成 `<html>` 上的类，主题 token（`--product-library-*`）和 color-scheme 继承进每个 Shadow DOM。`styles.css` 开头的一处桥接让每个 `--plus-*` 颜色读取 Todoist 赋予同一角色的 token；不再用脚本复制颜色，主题切换在同一次样式计算中生效。选中底色上的所有文字（含次要文字和今天的日期数字）都用 `selected-text`，强调色只放在页面、列和卡片底色上。

| `--plus-*`                    | Todoist token                                                                        | 用途                                  |
| ----------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------- |
| `accent`                      | `actionable-tertiary-idle-tint`                                                      | 文字链接、焦点框、插入线、投放边框    |
| `accent-fill` ／ `on-accent`  | `actionable-primary-idle-fill` ／ `-on-idle-tint`                                    | 主按钮、复选框及其上的文字            |
| `selected` ／ `selected-text` | `selectable-secondary-selected-fill` ／ `-on-selected-tint`                          | 选中的导航、过滤、日期和当前 Focus 卡 |
| `bg` ／ `surface` ／ `text`   | `background-base-primary` ／ `-tertiary`，`display-primary-idle-tint`                | 页面、列与日期列、正文                |
| `muted` ／ `line` ／ `hover`  | `display-secondary-idle-tint`，`divider-primary`，`actionable-quaternary-hover-fill` | 次要文字、分隔线、悬停层              |
| `warning` ／ `danger`         | `info-warning-primary-on-idle-tint`，`schedule-overdue-tint`                         | 提示文字；已过 N 天、错误边线         |
| `p1`–`p4`                     | `priorities-pN-primary-idle-tint`（API 的 4 是 P1）                                  | Review 与 Focus 的优先级圆圈          |
| `overlay`、`shadow-1`–`3`     | `background-overlay`，`shadow-raised-1`–`3`                                          | 弹窗背景、卡片／浮动条／弹窗阴影      |

`danger` 读 Todoist 自己给逾期日期的颜色：它原来读的 `info-attention-primary-idle-tint` 作 12px 文字在公开主题里只有约 4.1:1，低于 4.5:1；`schedule-overdue-tint` 在浅色主题为 4.54:1。每项保留原来的浅色值作后备，用于没有 token 的页面；扩展设置页声明 `color-scheme: light`。2026-10-16 owner 决定 Plus 没有深色模式：此前的 `light-dark()` 后备、按原生文字颜色给宿主加 `data-theme="dark"` 的脚本和 `:host([data-theme="dark"])` 规则都已删除，原型也不再有主题切换。`surface` 是 Todoist 的第三层背景，各主题都带自己的色调（Default 偏暖，Kale 偏绿，Blueberry 偏蓝）。任务详情里的“步骤与时间”背景透明，显示 Todoist 弹窗自身的底色。字体读 `--td-ui-font-family`。只有导航行的宽度和字号在挂载时测量。

`@doist/product-libraries-tokens` 1.4.2（MIT，只含 CSS）是固定版本的开发依赖，只用于测试，不进入构建包。单元测试拒绝 src 中该包没有定义的 token 名，例外只有在真实页面确认过的 `shadow-raised-1`–`3`；`--td-ui-*` 只允许同一次核对见过的 `font-family` 和 `button-normal-height`，运行时拼接的名称同样拒绝。浏览器测试用它的公开主题 CSS 检查默认主题和七个彩色浅色主题（Kale、Blueberry、Tangerine、Gold、Lavender、Moonstone、Raspberry）：Plus 实际组合的文字对比度至少 4.5:1，焦点框、插入线和投放边框至少 3:1，并在 Week 中实测今天的日期数字和选中事项的次要文字；还检查没有 token 时的浅色后备。公开值与真实 Todoist 可能略有不同，所以断言比较页面自身的 token，而不是写死的颜色。

### 恢复

Plus 隐藏原生界面的前提是替代界面已挂载，失败路径都恢复原生 Todoist：

- 任务详情先取包含任务正文区域的行，再取选择列表的第一行（它也可能是小步骤列表），没有列表时才取其他行；页面地址是任务链接（`…/task/<id>`）时必须指向同一任务，否则不挂载“步骤与时间”，不会写到别的任务。真实弹窗的结构待发布前核对，见[验证](verification.md#发布前页面核对)。
- Todoist 重建 `#content` 或侧栏时，Plan／Focus 视图和导航重新挂载，每分钟最多 10 次；视图未挂载期间不隐藏任何原生项，其他视图收藏只在 Other views 开关挂好后收起。挂载失败不会卡住后续挂载。Todoist 加入 `#content` 的对话框、提示和 toast（role 为 dialog、alertdialog、alert、status 或 aria-modal）保持可见。
- 渲染出错时只显示一行“返回 Todoist / 重新加载”；返回会去掉视图参数并恢复原生页面，切换到另一个视图会重新尝试渲染。页面检测在下一次成功渲染后才清除“显示出错”，侧栏重建不会清除。重建次数达到上限后，点击 Plan 或 Focus 会在上限窗口过后重新挂载。
- 页面观察每帧最多运行一次；只有 Plus 自己改动了页面（隐藏、恢复、渲染或宿主显示）的那次运行才计数，30 秒内超过 1,500 次视为反馈循环，Plus 卸下并恢复原生页面。Todoist 自身的滚动和拖动不计数，无论持续多久。每次运行、回到标签页和窗口获得焦点时检查扩展是否已停用或重新加载，是则立即恢复，无需刷新；加载新版本仍需刷新页面。

所有 Todoist 选择器集中在 `src/anchors.ts` 的一张表中，每项按表中顺序逐个尝试；Todoist 更新后只改这一处。

### 页面检测

扩展设置页显示一行最近的页面检测，语言跟随 Todoist：“Todoist 页面检测：全部正常”，或例如“步骤与时间已关闭（任务 ID 与页面链接不一致）”。content script 只在状态变化时发送固定集合中的键：增强项（计划和专注、步骤与时间）及原因（找不到侧栏、主内容区、任务详情区域或任务行，任务 ID 不一致，重建过多，页面持续变化，显示出错）。启动 15 秒后仍未挂载时只报告确实缺少的锚点；后台标签页不运行动画帧，等它显示后再重新计时。background 拒绝含其他键或值的记录，只把最新一条存入 storage.local，只给设置页读取；不含任务内容、ID 或网址，也不离开浏览器。

## 写入与读取

任务详情只为用户编辑过的规划范围、领域、截止日期和提前量保留局部草稿；其余字段随任务刷新。草稿对应字段在别处改变时，先提示“保留我的修改／使用最新值”，保存暂不可用；保留仅接受当前值作为新的比较基线，仍要再点保存。规划写入只提交改变的字段，截止日期写入沿用现有接口并保留最新未编辑提前量。估时与新增步骤沿用原流程。

2026-10-15 owner 批准：拖动先显示、按序保存，只对下列拖动与移出放宽“写入期间禁用写入控件”。

- Review 跨列拖动和列内排序、Week 拖入日期、“下一步”排序、跨日移动和同日排序落下后，卡片立即显示在预期位置。只有这张卡等待：变暗、小转圈、不可拖动，移出按钮隐藏。其他卡片、切周和下一次拖动照常可用。
- 等待确认的卡片在可访问名称中带“正在更新…”；抓手用 `aria-disabled` 停用但保持可聚焦，键盘落下后焦点留在移动的卡片上。减少动态效果时小转圈停止，只保留变暗。
- 等待确认的 Review 卡仍带拖动前的 etag：它的详情在确认或撤回前只读，详情标题显示同一等待标记；结束后显示服务端保留的规划范围。本周目标与任务无关，拖动期间照常可编辑。
- “移出日期”不提前删除：卡片原位等待，FlowDay 确认后才消失。
- 所有写入进入同一个先进先出队列，按操作顺序执行。FlowDay UpdateFlow 没有 etag、后写覆盖先写，所以移出日期和加入今天在执行时先 GetFlow 读取当前队列，只增删这一项，不写回屏幕上可能过时的队列；其他标签页刚加入的步骤和排在前面的移出都会保留。Todoist 写入仍检查 etag。确认后换成服务端返回的任务或队列。
- 任一写入失败时，排在其后的写入不再发送，所有等待确认的预期变化撤回；原有错误区域说明“更改未保存，已恢复”、实际失败和其后未发送的更改数，队列空闲后重新读取。等待确认的卡片不显示为已保存。
- 邮件页的归入（点一下即写入，没有菜单和确认框）和全部删除也是先确认后显示，但只让相关的行等待（变暗、PendingMark），其他行照常可用；邮件归类的保存只写 Todofy，在对话框里等待和报错。
- Week 的“添加步骤”（下一步托盘的一格输入）也先确认，但不打断打字：回车后标题先作为等待卡显示，输入框清空并保持打开，读取列出新步骤后换成步骤卡；一次只保存一个。
- 完成、在任务详情添加小步骤、估时、提前开始、标为进行中（含看板卡片的“开始”）、详情中的规划保存、添加或移除依赖、计划标签、本周目标、加入今天、计时以及周回顾中的移到本月、留到下周和完成回顾仍先确认，写入期间停用写入控件；本周目标和“沿用”只用 `aria-disabled` 标为不可用，保留焦点（见[本周目标](#本周目标)）。
- 依赖的核对（ResolveDependencies）在 Review 看板显示的完整读取之后于后台进行，每次读取至多一次，不进写入队列、不停用控件；它失败时不显示错误，下次完整读取再问。与它重叠的写入确认后，它的回答不合并，由下一次读取显示。

读取不锁定看板，也不重复读取写入已返回的结果：

- 打开、刷新按钮、返回标签页（距上次完整读取至少 60 秒）和写入后需要的读取都在后台进行，只转动标题栏刷新图标。与写入重叠的读取作废，队列空闲后再读，旧读取不会覆盖较新的确认结果；两次读取重叠时，先发出的读取晚到也不覆盖后发出的结果。
- SetTaskPlan（含标为进行中）、SetTaskLead 的 PlanningTask、SetWeeklyBet 返回的目标和确认后的日期队列直接合并，不再读七天；目标别处改过时只重读一次 ReadPlan。UpdatePlanLabels 的映射直接合并；新映射会改变任务的规划范围投影和全部任务 etag，所以随后后台读取一次，读取完成前停用写入控件。
- 完成任务后仍重新读取，不在本地删除：Todoist 关闭循环任务时会推进到下一次。读取完成前该步骤等待，不能再次完成。
- 离开 Plan／Focus 时，上次确认的数据只留在当前页面内存中；返回时立即显示，再后台读取。它可能早于一次完成或跨过午夜，所以本次读取完成前不开放写入；这次读取失败时只显示错误，并丢弃这份内存数据。离开时显示本周的，返回后跟随服务端的当前周（含周一轮换）。
- 原生页面只调用 ReadPlan。background 把 `{configured, hiddenFilterIds, labelIds}` 只按 ID 存入 storage.local，不含任务内容；下次打开 Todoist 时侧栏立即按缓存整理。连接缺失或失效时（包括网关对未知或已撤销口令的 401）清除缓存并提示打开连接设置；断开或换连接后仍在进行的请求不再写回缓存或 FlowDay ID。原生任务详情使用一分钟内读取、且包含该任务的内存数据时只调用 ReadPlan；更旧的或缺少该任务的先显示，完整读取完成前不开放写入。保存失败（例如任务已在 Todoist 中修改）后完整重读，不再复用旧数据。
- FlowDay 手动同步成功后记住请求的任务 ID，以及同步开始前最近一次完整读取列出的全部任务（Todoist 当时已有它们，这次同步一并导入；所以接连添加的两个步骤先后拖进日期，只同步一次），并只把 ID 镜像到 chrome.storage.session；后台 worker 被 Chrome 停止后仍可跳过重复同步，避免 30 秒节流内失败。

## 数据与接口边界

根 IDL 为 `proto/todofy/ui/v1/plus_service.proto`，FlowDay 的队列与计时 IDL 为 `proto/flowday/ui/v1/flowday_ui_service.proto`。修改 IDL 后使用根工具链生成客户端，应用不保存另一份协议。

| 用户操作             | 既有接口／本轮扩展                                                                               | 确认结果                                              |
| -------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| 加载                 | ReadPlan、完整 ListPlanningTasks、FlowDay ListTasks、七日 GetFlow、GetTimerSession               | 元数据、任务、所选周队列和真实今天计时                |
| 原生页面             | ReadPlan                                                                                         | 只按 ID 缓存配置，下次加载立即整理侧栏                |
| 改规划范围／领域     | SetTaskPlan（不再接受退役的 `bet`，带它的请求 BAD_REQUEST 且不写入）                             | 当前 PlanningTask，合并单任务                         |
| 标为／取消进行中     | SetTaskPlan 的 `active`：一次 `item_update`，只增删字面标签 `active`，从不创建它                 | 当前 PlanningTask，合并单任务；账户无该标签时拒绝     |
| 搁置／移出搁置       | SetTaskPlan 的 `parked`：加 `@parked` 时去掉规划标签和 `active`，从不创建它                      | 当前 PlanningTask，合并单任务；账户无该标签时拒绝     |
| 调整列内顺序         | ReorderTasks：列的顺序存 Todofy；移动卡片的兄弟任务交换 `child_order`，等待中、搁置除外          | 保存的列顺序和这些任务新的 `child_order`，直接合并    |
| 保存、清空、沿用目标 | SetWeeklyBet：`{week_start, area, text, etag}`，只写 D1 `plan_notes`，0 次 Todoist               | 返回的 WeeklyBet 直接合并；冲突时重读一次 ReadPlan    |
| 保存列标签           | UpdatePlanLabels                                                                                 | 带 etag 的精确标签映射，任务标签不改；后台重读投影    |
| 创建小步骤           | AppendTaskSteps                                                                                  | 原父任务下新步骤的 ID（按输入顺序），后台再读取       |
| 同日队列             | UpdateFlow                                                                                       | 确认后的目标 FlowDayPlan，直接合并                    |
| 移出日期／加入今天   | GetFlow 读取当前队列，再 UpdateFlow 只增删一项                                                   | 确认后的该日 FlowDayPlan，直接合并                    |
| 跨日队列             | RolloverFlow，再 UpdateFlow 排列插入位置                                                         | 确认后的源／目标 FlowDayPlan，直接合并                |
| 估时                 | FlowDay UpdateTask 的 estimated_minutes 掩码                                                     | 现有手动估时，零表示清空                              |
| 计时                 | CommandTimer，etag 与稳定 request ID                                                             | TimerSession 映射为 TimerSnapshot；idle 清除显示状态  |
| 真正完成             | CompleteTask，再结算 FlowDay                                                                     | Todoist 确认后后台重新读取，不靠本地删除              |
| 提前开始             | SetTaskLead                                                                                      | 确认后的 PlanningTask（Deadline、leadDays），Due 保留 |
| 周回顾数据           | ReadPlan 的邮件项目、回顾任务、下周选择 ID 和上周至下周的目标；ListPlanningTasks 的 update_time  | 与加载一同读取，不另发请求                            |
| 依赖                 | ReadPlan 的 `dependencies`（FULL）；PlanningTask 的 `recurring`、`completed_count`               | 只有 ID 与计数，与加载一同读取                        |
| 添加／移除依赖       | SetTaskDependency：只写 Todofy 的规划库，不写 Todoist                                            | 这个任务确认后的依赖，直接合并                        |
| 核对依赖             | ResolveDependencies：Review 显示的完整读取后，最多 20 个待核对的 ID                              | 全部依赖和不再等待的任务（删除或说不出），直接合并    |
| 移到本月／留到下周   | SetTaskPlan（stage monthly／committed）                                                          | 当前 PlanningTask，合并单任务                         |
| 完成回顾             | CompleteTask，不带 flow_date                                                                     | Todoist 确认后后台重新读取                            |
| 打开、刷新邮件页     | 现有的完整读取，再按 200 个一批 LookupMailItems（只读 D1）                                       | 邮件条目、归类及其 etag；只放在页面内存里             |
| 展开一封邮件         | ReadMailSummary（一次主键读）                                                                    | 纯文本总结；只放在页面内存里                          |
| 归入                 | FileMailItem：一次 Sync，回执；有归类时先 `item_update` 标签和优先级；`item_move` 到账户的收件箱 | 当前 PlanningTask（已在收件箱），合并单任务           |
| 全部删除             | DeleteMailItems：全新读取后只删未动过的，`item_delete` 先冻结进回执，每次 Sync 至多 100 条       | 删除和保留的任务 ID；删除的任务直接从计划中去掉       |
| 邮件归类             | ReadMailSettings、UpdateMailSettings（整组替换，只写 D1，可为空；`destination` 固定发 `inbox`）  | 保存后的归类和 etag；不再读取去处和项目               |

background 持有连接口令，content script 只发送封闭的类型化消息。升级沿用原目录和 storage.local 的 connection，不重置口令。Plan 的视图状态用非操作消息 `planView`（`src/plan-view-state.ts`）：不带 patch 时读取，带 patch 时只合并改动的字段并返回合并结果；background 依次合并，两个标签页改不同字段互不覆盖，形状和上限之外的（未知字段、不是 ID 的值、超过 6 行或 200 个保留项）一律拒绝，只接受 Todoist 页面发来的消息。当前内部操作消息使用 planning protocol 6（3：写入返回确认结果，新增 ReadPlan，加入今天与移出日期改为单项操作；4：本周目标改为文字的 setWeeklyBet，不再发送 `bet`；没有保存的目标以 `{notSaved}` 值跨过消息边界，页面再抛出 BetNotSaved；5：邮件页的六个操作；6：邮件归入收件箱，不再选去处，归类可以为空；搁置、列内与下一步排序（ReorderTasks））；旧脚本收到明确刷新提示，刷新 Todoist 后使用新语义。初次读取并行获取独立数据；切周只读七天队列。App 合并确认任务、标签映射、队列和计时响应，原有读取序号保护正在查看的周，Plan／Focus 切换不扫描所有任务。离开自定义页面进入原生 Todoist 后卸载，返回时先显示内存中的上次确认数据，再后台重新读取；读取完成前不开放写入。
