# 规划界面与接口说明

Tasks 的 Plan、Focus 和邮件归类对话框由本包提供（[README](../README.md)）；宿主见 [Tasks](../../../tasks/README.md)，原生验收见[对照表](../../../tasks/docs/planning-parity.md)。文中的标记（`waiting`、`blocked`、`parked`、`onhold`、`quick`、`active` 等）是 Tasks 任务的规划标记（planning flags），不是普通标签；“规划范围”是任务保存的 stage。日期是各项 owner 定稿的日期；2026-10-17 以前的定稿最初做在已退役的 Todoist Plus 扩展里（[历史](../../../docs/history/todoist-plus.md)）。代码路径相对本包。

## Plan 的组成

Plan 顶部保留当前账户周的本周目标，下方有 Review 和 Week 两个视图。第一次打开默认 Review 和 All，工作／生活过滤不改变任务。浏览另一周只影响 Week 的日期队列，不把当前承诺或本周目标伪装成历史快照。

卡片左边的色条是领域（2026-10-19 owner 决定），Plan 和 Focus 只用这一条规则（`areaColor`，`src/planning-outcomes.ts`）：按任务的领域，自己的，否则最近一层父任务的。工作是 `--plus-area-work`（#6387a3，灰蓝），生活是 `--plus-area-personal`（#a98369，赭石），未分类不着色，只是卡片自己的边线色 `--plus-line`。它用在 Review 和 Week 的事项卡（含选中的）、“下一步”托盘的标题条和步骤卡、快速事项、日历里的步骤、Week 的拖动浮层、Focus 的卡片和所属任务条上；元素设 `--area-color`，CSS 一律读 `var(--area-color, var(--plus-area-none))`。Plan 不列出的任务（例如别处刚完成的步骤）不着色。Review 和 Week 的领域过滤里，“工作”“生活”标签前的 8px 圆点就是图例，“全部”“未分类”没有圆点。颜色不单独表达领域：事项卡的可访问名称带领域，快速事项标题按钮的名称是完整标题加领域（`, Work`／`，工作`），下一步属于托盘标题里的事项，日历卡片下一行写着所属事项或领域。工作和生活的色条对 `--plus-bg` 约 3.8:1 和 3.2:1，满足非文字界面的 3:1。

Review／Week、Review 的领域过滤、本周周回顾是否展开及勾选、Week 选中的承诺和“本周承诺”的折叠由宿主保存（Tasks 存在浏览器 localStorage 的 `tasks.plan-view`，只有 ID 和行号，按字段合并写入），离开再回来、浏览器后退和刷新后恢复（2026-10-17 owner 决定）。Plan 挂载时读一次，之后只在用户改动时写入改动的字段，单纯打开不写入。记住的承诺已不在本周承诺里时选第一个，记住的领域不再出现在过滤里时显示全部；读不到时用默认值，存不进时页面照常工作。Week 自己的领域过滤不记住。同一字段在两个标签页里先后改动时以后改的为准。

### 本周目标

2026-10-16 owner 定稿：工作、生活各一行用户自己写的文字（最多 160 个 UTF-16 单位），原地编辑，存在 Tasks 的 D1（`weekly_bets`，按账户周一和领域；2026-10-20 起，之前在 Todofy 的规划库），不写入任何任务，与任何任务、承诺或标签都没有关联。

- 位置不变，在 Review／Week 上方；两列“工作／Work”“生活／Personal”，窄于 650px 时上下排列；只显示当前账户周，Week 翻到别的周不跟着变。
- 已写：目标文字本身就是编辑按钮（14px、600、可换行、纯文本、不识别链接），悬停时 `--plus-hover` 底色和文字光标，没有铅笔图标；按钮名 `编辑工作目标：{text}`／`Edit work goal: {text}`。
- 空：13px 灰字按钮“写下这周的工作目标”／“Write this week's work goal”（生活同理）。
- 空、上周有：下面多一行 12px 灰字“上周：{text}”，单行省略，完整内容在 `title`；悬停或焦点在这一列时旁边出现强调色的“沿用／Keep”，没有悬停的设备上一直显示；按钮名 `沿用上周的工作目标：{text}`。点一下把上周的文字写成本周的，焦点落在保存好的目标上。这是延续目标的唯一入口。
- 编辑中：原地换成同字号、同位置的一行输入框（`maxlength=160`），占位“这周最想推进的一件事”，标签“本周工作目标”，提示“回车保存 · Esc 取消”（输入框的 `aria-describedby`），剩 20 字以内时加“ · 还可输入 {n} 字”。计划页里提示放在这一列标题行的右端，整块高度不变，下面的看板不动；周回顾里仍在输入框下面一行。保存中输入框只读，末端显示 PendingMark“正在更新…”。
- 焦点框画在目标按钮内侧（`outline-offset: −1px`，同输入框），按 Enter、Esc 或“沿用”回到目标时不压到上面的列标题。
- 别处改过（ETAG_MISMATCH）：输入框下一行 `role=alert`“这条目标已在别处改过。再按回车会用你的文字替换它；按 Esc 查看最新内容。”，草稿保留，同时重读一次 GetPlan 显示最新内容；之后只有 Enter 或 Esc 决定。
- 这一周已结束（ACTION_NOT_ALLOWED）：`role=alert`“这一周已经结束，没有保存。”，草稿留着，Enter 不再写入，Esc 关掉；随后后台重读新的一周。
- 保存失败：现有横幅“未确认保存成功，请重试。”，草稿留在输入框里。
- 未配置、断开或维护中：现有 fieldset 停用，横幅不变，目标文字照常可读。

什么时候保存（`src/BetText.tsx`）：

- 在目标上按 Enter 或 Space 打开编辑框，光标放在末尾。
- Enter 保存；输入法组字时的 Enter（`isComposing` 或 keyCode 229）不算，中文输入不会提前保存。文字没改时直接关掉，不写入。
- Tab 或点页面里别的地方：文字改过且不为空就保存，焦点不动。切换窗口、切到别的应用或标签页被隐藏（`document.hasFocus()` 为 false）不保存，草稿保持打开；Plan 被重新挂载时草稿丢弃，也不写入。
- 离开时框是空的不清空，恢复原来的文字；只有在空框里按 Enter 才清空这一周的目标（保留这一行，正文为空，rev 加 1）。
- Esc 取消，恢复原文，焦点回到目标。
- 按 Enter 或点“沿用”之后焦点落在保存好的目标上；因离开而保存时焦点不动。
- Tab 顺序：工作目标 →（沿用）→ 生活目标 →（沿用）。每列标题是 h3，整块的 aria-label 仍是“本周目标”。
- 结果由隐藏的 `role=status` 读出：“已保存工作目标”“已清空工作目标”“已沿用上周的工作目标”（生活同理）。这个区域一直在，只换文字（`src/announce.ts`）；同一句话连着出现两次时先清空、100ms 后再写，第二次也会被读出。
- 其他写入等待确认时，目标和“沿用”只用 `aria-disabled` 标为不可用（目标变暗、“沿用”变灰且仍只在悬停或焦点时出现，点击无效），不用 `disabled`：否则 Tab 刚移到另一行目标上的焦点会被它自己那次保存夺走。

写入是 UpdateWeeklyBet：只写 D1，不写任务，也没有回执；先比较，文字与已存相同就直接返回已存的目标（所以丢失回答后的重发、跨过周日午夜的重放都安全，请求不带 request ID），否则只接受本周和下周，再按 rev（etag）写入一条。返回的 WeeklyBet 直接合并进 `plan.weeklyBets`，不再读取。GetPlan 在同一批 D1 查询里读上周、本周和下周的目标，最多 6 行。

### Review

从左到右是“搁置／Parked”和 Quarter、Month、Week 三个竖排规划列；Committed 在下方独占一行，卡片横排。Parked 和规划列始终显示，Waiting 列已移除。宽度不足时沿用现有两列、单列响应式布局，Committed 始终另起一行。

2026-10-25 起，全部依赖完成或 Deadline 进入启动窗口的未开始任务自动浮现在 Parked。它也可以是已有规划范围的任务；这里只改变看板位置，保存的阶段、日期和 Focus 队列保持原样。本周承诺例外：它留在 Committed，卡片显示同样的状态和 Start，与 Week 的承诺总览、工具栏计数一致。仍有未完成依赖或显式 Waiting／Blocked 的任务及其后代不在 Plan 展示；已接手 Active 的任务不自动浮现。没有依赖不算“依赖已完成”。原有手工拖入 Parked 的功能保留，只有手工搁置才保存 `parked` 标记。独立 Start now 列不再展示；旧 lane order 的 `start` 键仍可读取。

每个可见任务只出现一次：手工搁置与自动就绪项（本周承诺除外）进入 Parked，其余有规划范围的留在原列，日期候选沿用原来的 Week 规则。等待项在整个 Plan 隐藏，即使保存了规划范围或 Parked 标记也一样。Week 的承诺、步骤、Quick 和日历同样隐藏等待项，存储的数据和 Focus 照旧。Parked 的自动项按截止日期、优先级排列，新出现的项在已排列项前；手工搁置项排在自动项之后，按既有顺序或未变动时间显示。自动项全部展示，手工积压先展示三项，可展开其余。

自动项卡片显示截止状态或“前置任务已完成／Prerequisites completed”。点击 Start，或把就绪卡（Parked 的自动项、启动窗口内的承诺）拖入另一规划列，在一次现有 UpdateTask 中加 `active`，之后不再因同一条件返回 Parked。拖动同时保存目标阶段；点击 Start 保留原阶段。手工搁置项拖出时清除 `parked` 并保存阶段；它的启动窗口已开或依赖已全部完成时，同一次写入也加 `active`，否则它会立刻作为就绪项回到 Parked。拖入 Parked 仍是手工搁置，会清除阶段及 Active。

卡片仍是 77px 高、最多两行标题、底部一行 12px 状态或步骤统计，左边色条区分领域；优先级用原来的小旗标。截断标题由 FullTitle 提示完整文字，完成勾选与整卡拖动保持现有行为。同列投放到卡片上保存顺序；跨列投放先预测落点，确认后保留，失败回到原位。步骤不会因拖动变成另一个任务或被移出原父任务。

### Week

上方紧凑总览显示当前 Committed 事项，与 Review 的“本周承诺”一列是同一组、同一顺序（搁置的不在其中）。默认展示全部，工作／生活过滤保持可选。单击一个事项选中它、展开它的小步骤，再从步骤托盘拖入日期；双击打开它的任务详情（见[单击与双击](#单击与双击)）。承诺卡可以拖动排序（2026-10-19 owner 决定）：它就是 Review 的“本周承诺”一列，落在另一张承诺卡上占据它的位置，写入同样的 ReorderTasks（列 `committed`），两边的顺序始终一样；左边 25px 内边距里是与 Review 相同、一直显示的抓手（“移动承诺：标题”），键盘从抓手拿起，左右键在卡片间移动，落下后焦点回到它的抓手；读屏读出“移到：本周承诺第 2 项”。只接受承诺卡：步骤落不到承诺上，承诺也拖不进日期。所以一张承诺卡上单击选中、双击打开、拖动 6px 排序，互不干扰。没有自己规划范围的中间层级和仅因日期进入候选的子步骤继续属于父事项；保存了不同规划范围的子事项按自身范围处理。只有步骤（`kind=step`）和选择 Standalone 或 Quick 的任务能排进日期。日期不重写。

步骤卡先显示标题，下方显示短所属事项和估时；左边色条是领域（见[Plan 的组成](#plan-的组成)）。事项卡与 Review 的同高（77px），标题最多两行，被截断时悬停或键盘焦点显示全文。本周承诺全部显示，超过一行自动换行；5/3 只是提示。网格按宽度排列，每张卡至少 220px：1440px 窗口 4 列，1024px 3 列，800px 和 680px 2 列。“下一步”卡片固定 60px（2026-10-19 owner 决定），宽度跟托盘的等宽三列（窄托盘一列）：一行 14px 标题、一行 12px 估时和已排的日期（`30m · 周二`，没估时写“未估时”），两行都以省略号截断，长网址也不撑宽卡片；长标题在鼠标悬停或键盘焦点约 350ms 后在标题下方浮出全文（最宽 320px，最多 6 行，不挡指针，拖动时不出现），读屏读到的按钮名就是完整标题。估时 2 小时以上时估时用警示色，这就是全部提示，卡片上不再另写一句。添加步骤的等待卡同样 60px、一行标题，等待标记在标题后面。日历里的步骤标题最多三行，完整标题在 `title` 里（日期列会裁切浮出的全文）。下一步、快速事项和日历卡的抓手是 14px 的浮层，放在卡片左边的内边距里（下一步 14px，快速事项和日历卡 12px），平时透明，只在鼠标悬停这张卡或键盘焦点落在抓手上时出现，标题不移动；标题因此比以前宽（日历卡和下一步约 25px）。实际数据没有额外保存色彩设置或像素布局。

“下一步”按 Tasks 的子任务顺序列出（2026-10-17 owner 决定）：逐层深入，每个父任务的子任务按同级位置（`sort_order`）。同一父任务下的步骤可拖动或用键盘调整顺序：拖到兄弟步骤上时，三列托盘里那张卡的左边（往前移）或右边（往后移）、单列托盘里它的上方或下方出现 2px 强调色的线，落下后占据它的位置；落在别的父任务的步骤、“添加步骤”或等待卡上不写入，拖到日期照常安排。一次 ReorderTasks 把这个父任务的全部子任务（包括有自己步骤的）按新顺序交换原有的位置，只改任务的顺序，不存列的顺序；位置缺失或重复时，或子任务超过一次请求能带的 100 个时不写入。落下后先显示，步骤变暗等待，失败时撤回。键盘：抓手上空格或回车拿起，方向键在兄弟步骤和日期之间逐个移动，空格或回车放下，Esc 取消；落下后焦点留在它的抓手上。

日期队列保留原始顺序、本地任务、杂项与已完成 ID。托盘拖动给目标日增加安排，同一小步骤可以安排在多日；拖动日历中已有卡片才从原日移到目标日。投放到卡片前表示插入到它前面；投放到列底部表示追加；同日拖动调整顺序，插入线是 2px。跨日移动先确认源／目标队列，再在目标位置插入。落下后卡片立即显示在新位置并等待确认，见[写入与读取](#写入与读取)。已运行或暂停的步骤需要先停止计时。

已完成的步骤留在日历里（2026-10-20 owner 决定；Focus 不变）：日历卡片勾选完成后，重新读取时它不再离开，而是留在它那天，排在未完成的步骤之后，按队列顺序（Tasks 分别列出一天未完成和已完成的步骤，不给两组之间的相对位置）。样式同 Focus 的“已完成”，也就是任务列表已完成行的样式：内容 0.72 不透明，标题 muted 加删除线，勾选框是填满强调色的圆加勾，与未完成卡片的勾选框对齐；色条和下一行（所属事项、估时）照旧，Plan 不列出它时用它父任务的领域色（同 Focus）。它不能拖动、移出或再次完成，也不是插入的落点（可重复的步骤在 Plan 里仍未完成，从托盘再拖入这一天时 Tasks 重新打开这天的标记，所以它落下后立即作为未完成步骤显示并等待确认）；日期标题的总时长只算未完成的步骤。唯一的控件是标题，可访问名称“已完成: 标题”／`Completed: …`：它打开 Tasks 自己的任务对话框，在那里可以重新打开（规划面板需要未完成的任务，Plan 的接口没有重新打开）；宿主没有 `onOpenTask` 时标题只是文字，读屏同样先读“已完成”。一天里两组都有时，中间是 10px 的列底投放带，投放仍追加到未完成步骤的末尾；只有已完成的步骤时，“拖入步骤”在它们上方。标题和估时来自 Plan，否则来自 Tasks 的 Focus 读取：加载和切周的 ListFocusDays 都列出这一周队列提到的任务，切周的 `loadDays` 返回 `FocusRange`，App 把其中的任务并入 `FocusState.tasks`，所以别的周的已完成步骤也有标题；Tasks 没有列出时显示“任务暂不可用”。

日历显示上一周、下一周、回本周。日历内容区大于 960px 时显示七日（常见 1440px 桌面窗口），420–960px 显示三日，更窄时显示单日；三日和单日布局的上方日期按钮仍可选日和投放。显示其他周不修改任务 Due 或 Deadline。日期队列变更不修改规划列。

承诺总览标题行内有一段安静的文字“N 项承诺这 7 天还没有安排”：承诺本身和它未完成的步骤都不在所显示 7 天的队列中。只在 N 大于 0 时出现，没有逐卡标记；点击依次选中下一个这样的承诺，展开其步骤托盘，按钮提示“选中下一个”。它只提示，不自动安排。

“本周承诺”标题本身是折叠按钮（2026-10-17 owner 决定），默认展开，折叠与否和选中的事项都会记住（见[Plan 的组成](#plan-的组成)）。样式同分区的折叠：16px 的 Lucide 箭头在标题左侧的留白里，标题仍与下面的卡片左缘对齐；箭头展开时只在悬停标题行或键盘焦点时出现，折叠时一直显示；按钮保持标题的 15px、600，悬停时 `--plus-hover` 底色。折叠和展开时标题行不移动（看不见的领域过滤仍占着位置）。折叠后只留标题行“本周承诺 6 项”（不重复选中事项的标题，下面托盘的标题就是它）、那行未安排提示和“下一步”托盘；没有选中事项时托盘位置写“展开“本周承诺”，选择一个事项。”。领域过滤和事项网格折叠时仍在页面里（`hidden`），所以按钮的 `aria-controls` 始终指向网格。“周回顾”的“去安排”会展开它。

### 任务执行方式

Step、Standalone 和 Quick 在 Plan、Focus 中共用估时面板，原生任务详情也提供可选的 Estimate。日期中的具体时间仍可设置。日历优先显示任务已设的时刻（按任务时区，未设时按账户时区），其次是估时；既没有时刻也没有估时的 Quick 写 Quick，不显示“?”，也不计入未估时数量。Focus 卡片和“下一步”托盘同样先显示 Quick 的估时。已有估时和用时记录保留，不自动填一个固定时长。

原生任务详情和 Plan 的任务编辑器共用 `ExecutionFields`（`src/ExecutionFields.tsx`）：Execution 的分段单选为 Steps、Standalone、Quick，旁边是独立的 Routine 开关。Steps 安排任务下的小步骤，清除 `task`、`quick`；Standalone 直接安排任务，设置 `task` 并清除 `quick`；Quick 同时设置两项。这不会改变 `kind`，已有 `quick` 也按可独立安排处理。

任务编辑器不再提供进行中、等待中、暂缓或搁置的手动开关。保存的 `active`、`waiting`、`onhold`、`parked` 保留原有含义，修改 Execution、Routine 或其他无关字段时不清除它们。选择规划范围仍移出搁置；看板的“开始”和拖动、依赖与截止日期规则照旧。原生详情的 Steps、Subtasks 各在标题行提供 Add step、Add subtask，展开对应输入框。

布局参照 Tasks 的[已确认界面](../../../tasks/docs/images/task-interface-approved.png)；侧栏的分组和项目树由 [Tasks](../../../tasks/docs/design.md#task-interface) 管理。

### 步骤面板

2026-10-19 owner 决定：步骤（`kind=step`）的规划范围和领域跟随所属事项，它唯一的规划信息是用时。所以在 Plan 和 Focus 里打开步骤时，弹出的是只设用时的面板（`src/StepEditor.tsx`），外观与任务详情相同：标题和关闭按钮，“在任务详情中编辑日期、描述和项目。打开任务”一行，所属任务条（领域色），然后一行“预计用时 [15 分钟] [30 分钟] [60 分钟] [90 分钟] [自定义]”。对话框以标题命名。

- 规划范围、领域、Execution、Routine、子任务、添加步骤、截止日期和依赖都不在这里，“打开任务”打开 Tasks 的完整任务详情。
- 选择立即显示为按下，这一步的卡片变暗等待，标题旁出现等待标记；宿主写 Tasks 的 `duration_minutes` 并返回保存的时长和任务新的 etag（`{ estimate, etag }`），确认后直接合并，不整表读取，按下的预设不会闪回旧值。等待期间预设只是 `aria-disabled`，不响应点击，焦点留在按下的按钮上；面板只按任务 ID 挂载，保存不会重新挂载它。保存后读屏读出“已保存预计用时：60 分钟”。失败时现有横幅说明“更改未保存，已恢复”，按下的预设回到已存的值。

### 截止日期

Start ahead 接受真实 Deadline 前 0–365 天，按 Tasks 的账户日期及现有 `must_start` 计算。窗口已开或已过截止、并且可开始的任务自动进入 Parked；窗口未开时只在详情显示启动日期。没有配置提前量时，沿用现有规则：在周回顾提示设置，已过截止则进入 Parked。未完成依赖或 Waiting／Blocked 仍优先等待；Active 与手工 Parked 不触发自动浮现。

卡片保留“还剩 N 天”“今天／明天截止”和红色“已过 N 天”，完整日期在提示中。自动项有 Start 操作，沿用原来只改变透明度的悬停／键盘显示，不挪动标题和完成按钮。确认后任务回到保存的规划列，或在没有阶段时离开看板。Week 的承诺总览继续只显示步骤和排程数量。

任务或其未完成后代还没安排进本周队列时，Focus 显示待安排提示；点击定位 Parked。这里不创建通知、不插入执行队列，也不修改计划日期或 Deadline。

### 等待任务

Plan 不展示 `waiting`、`blocked` 或仍有未完成依赖的任务及其后代，也不在周回顾放等待项入口。原任务、阶段、顺序、排程和计时记录保留；用户仍可在 Tasks 列表和详情查看、编辑依赖。全部前置完成后，可开始的任务自动在 Parked 浮现。此过滤不影响 Focus 原有内容。

### 依赖

2026-10-16 owner 定稿（设计 plus-next §2，数据层 §5.1）：一个任务可以等其他任务完成。依赖存在 Tasks 的 D1（`task_dependencies`），记在等待的任务上，是两个任务 ID 之间的一条边；不写进任务的标题、描述或标签，也不设 `blocked`。它只影响显示：全部前置任务完成后，未开始的后续任务自动浮现在 Parked，不改日期或保存的阶段，也不写普通标签。旧标题后缀 `<k:… dep:…>` 在 Plan 里隐藏。

规则（`src/dependencies.ts`，完整读取之后）：

- 所等的任务 B 在活动列表里、Tasks 也没说它已完成就在等；B 不在活动列表里就算满足（“消失即满足”）。B 被删除时，Tasks 删掉等它的依赖；A 完成时，删掉 A 的依赖。B 所在的项目归档时，Tasks 也答 `done`，与 Plan 一致。被重新打开的 B、项目恢复后的 B 又出现在列表里时重新算在等。
- 循环任务完成时只推进日期、ID 不变：任务的 `completed_count` 在每次完成时加一、撤销时减一。建立依赖时 Tasks 记下 B 当时的计数，B 在那之后的下一次完成（计数大于记下的值）就算满足，Tasks 在每个依赖上答 `done`，以后的循环不再挡住 A；要等 B 的再下一次，就在选择框里再选一次 B，从当时的计数重新记起。Tasks 对集合里已有的依赖保持原样，已满足的也不重新开始，所以 Plan 先发不含 B 的集合，再发含 B 的集合（两次 UpdateTask）。
- 只有仍在等的依赖算数：每个任务最多等 5 项，全部最多 300 条；不能等自己，也不能互相等待（含经过其他任务的环）。已满足的依赖不构成环，也不占 5 项：任务已有 5 条（或全部已有 300 条）时，它最早一条已满足的依赖给新的让位。选择时就不让选；Tasks 写入时用一次读取再查一次，并在同一个批次里再核对环和 300 条，两个标签页同时写也不会成环。

**任务详情的“依赖 / Depends on”段**：在 Plan 的任务详情里，位于“截止日期”段之后，标题样式与“下一步”“截止日期”相同。

- 每个尚未满足的依赖一行：13px 标题按钮（在 Plan 中打开它的编辑器），循环任务右侧写 `下一次完成后 / After its next completion`；最右是 24px 的 ×，可访问名称 `移除依赖：订场地`，平时透明度为 0，只在悬停或键盘焦点进入这一行时出现，没有悬停能力的设备一直显示。
- 已满足的不逐条列出：全部满足时写 `所等的任务都已完成，可以开始了 / Everything it waits for is done — ready to start`，部分满足时 `另有 1 项已完成 / 1 more is done`。这一行右端同样有 24px 的 ×（`移除已完成的依赖 / Remove the done dependencies`），只在悬停或键盘焦点时出现，一次排队写入移除这些已满足的依赖，读出 `已移除已完成的依赖`。不移除时，它们在这个任务完成或删除时由 Tasks 删除，或给新依赖让位；循环任务一直在列表里，所以这一行会留到移除或被新依赖替换为止。
- 有任务在等它时多一行只读文字：`「发邀请函」在等它`，多个时 `「发邀请函」等 2 项在等它`。
- `+ 添加依赖 / Add a dependency` 是 `.plus-text-button`；已有 5 项仍在等时停用，`title` 为 `最多 5 项 / Up to 5`。
- 行高 32px（含下边线），带 × 的已保存行和带等待标记的待确认行一样高，确认时不跳动。标题按钮平时像普通文字，悬停或键盘焦点时加下划线，表示点它会打开那个任务。

输入法组字期间，Enter、方向键和 Escape 交由输入法处理，不移动选项或添加依赖。选择框是内联的，不在 Plan 的对话框里再套一层：32px 输入框自动获得焦点，占位文字 `搜索任务或父任务 / Search tasks or parents`；输入后在已完整读取的活动任务中按标题或父任务即时搜索，规则与原“更换目标”相同，没有语法；没有输入时不列出任何任务。结果最多 6 行，每行至少 28px：标题 13px，右侧是父任务路径（12px muted）。不列出任务自己、它的父任务和它的步骤，以及它仍在等的任务；已满足的循环任务会再列出，选它就等它的下一次完成。会形成循环的任务（按仍在等的依赖）仍列出但为灰色，右侧写 `会互相等待 / Would wait on each other`；灰色的行不能选择，也从不高亮：高亮从第一个能选的行开始，↑↓ 只在能选的行之间移动，鼠标移到灰色行上不改变高亮，Enter 添加高亮的那一行；Escape 或 `取消 / Cancel` 收起选择框，Escape 不再传给外面的对话框，焦点回到“添加依赖”。

选中即写入，是先确认的一次 UpdateTask（mask `dependencies`，带 Plan 持有的 etag 发送这个任务的新的依赖集合；再选已满足的循环任务时是先移除再加入的两次）：新行先带现有的等待标记（PendingMark）显示，写入期间停用写入控件，确认后合并返回的这个任务（新的 etag）和它的依赖，不再整表读取；编辑器的 `role="status"` 读出 `已添加依赖：订场地`。点 × 同样是一次写入，读出 `已移除依赖：订场地`。失败时用原有错误区域：Tasks 拒绝时写 `Not added: this dependency cannot be added now. Refresh and try again.`（别的标签页刚改过依赖成环、到了上限或所等的任务已不在待办中都是同一个拒绝，所以不猜原因；和其他 API 错误一样只有英文），任务已不存在时写 `Not added: one of these tasks is no longer active. Refresh and try again.`。

**看板与其他位置**：等待任务及其后代不在 Plan 的看板、Week、步骤、Quick 和日历出现。完成前置后，未开始的后续任务在 Parked 显示“前置任务已完成”。任务详情仍显示具体依赖和完成情况；Focus 保留已有队列和记录。

依赖写在等待的任务上，算作改动它：“等待中”的“N 天未变动”从这次写入重新计起（2026-10-20）。

详情中另有只读 Dependents／依赖此任务，列出仍存在的活动任务及可点击标题；没有添加或移除按钮。原生详情随 GetTask 一次读取，Plan 详情复用已加载的完整依赖图。

### 周六选择留到下周

规划周按账户时区从周日开始，到周六结束。周六结束进入周日 00:00 时，旧周未完成承诺读作 Week 候选；周日选入 Committed 的事项属于当前新周，周一不会再回退。资源名称和已有数据继续用周一日期作为周 ID：周日映射到次日周一，周一至周六映射到本周一。周目标、历史和每日队列不迁移、不删除。

周六在 Plan 中写入 `stage=committed`，或在回顾第 5 行点击“留到下周”，把该事项记为下一规划周，周日保留。只改领域、估时、步骤或排序不续期。第 5 行在周六提供承诺保留和下周工作、生活目标编辑；周日只提供本周工作、生活目标编辑（承诺已经轮换）；其他日子说明周六可以操作。周日开始空着的本周目标仍可用“上周：… · 沿用”取回上一周文字，本周目标区和周日的第 5 行都可以。

周日 10:00 的既有回顾任务调度及历史 ISO review ID 保留，作为上一周的执行回顾。Plan 的清单和目标使用当前规划周的稳定周 ID。日期选择器和 GTD 的周范围、月历行也从周日开始。

## Focus 与计时

Focus 显示 Tasks 的今天（`ListFocusDaysResponse.today`，即账户时区的今天）的未完成队列，顺序与 Week 相同。队列、计时和用时记录都在 Tasks 自己的 D1（`proto/tasks/ui/v1/focus.proto`）。Plan 按 Tasks 的今天（`PlanState.today`，GetPlan 的 `today`）排列和计算状态，与 Focus 是同一天。卡片标题在上方，短所属事项、估时和已用时间在下方。空队列只有“调整计划”入口，不出现另一套任务挑选器。

**视图与日期**：Focus 保留每日执行列表。标题下方是 28px 的前一天／后一天箭头和“今天”按钮，已在今天时按钮不可用；同一行右侧的“查看统计”／`View statistics` 通过 `onOpenGtd("time")` 打开 Tasks 的 GTD Time。页面副标题显示当前日期和账户时区，下方不重复日期。普通进入从今天开始，从 GTD 选择日期时由宿主传入 `focusDay`；之后前后翻日只影响当前 Focus 页面。日期和“已完成”勾选不保存到浏览器。没有键盘快捷键。

摘要下方按原因提示还没安排的就绪项：已过截止、已到启动窗口、前置任务已完成。只数 Plan 展示的任务（等待中的任务及其后代不算），任务本身或未完成后代已在本周队列时不计入，每项只数一次。点击打开 Plan › Review 的全部领域并定位 Parked。它只在今天出现，不自动往队列加任务。

**今天的“日”**：摘要一行分两组，可换行。左边是未完成步骤的估时合计、步骤数、未估时数，再是“· 已用 2h 5m”／“· 2h 5m logged”：当天的记录加上计在这一天的进行中或暂停的计时，大于零时才显示，每秒只更新这一小段（`LoggedTime`，`src/StatusMarks.tsx`），整页不重绘。右边（`margin-left: auto`）是计时方式和“调整计划”，窄时整组换到下一行，仍靠右。计时方式默认“正计时”，排在最前，另有 25 分钟、50 分钟；名称“计时方式”／`Timer duration` 不变。正计时就是 owner 说的“完成一个步骤用了多久”：开始，做事，然后勾选完成；完成的那次 Tasks 写入结束这段计时，并存下它的用时。

每个 Tasks 步骤显示独立的完成控件和计时按钮。完成控件是优先级圆圈（P1 红、P2 橙、P3 蓝带浅色底，P4 灰），与 Review 卡片一致；Plan 没有列出的任务（标题和所属事项来自 Tasks 的读取）没有完成控件，保留同宽空位，标题对齐，它的色条跟随 Plan 列出的父任务，否则不着色。卡片下方一行是“预计 30m · 已用 35m”／`Est. 30m · 35m logged`，没有估时写“未估时”，没有记录时写“记录时间”／`Log time`。“已用”是一个安静的按钮（12px，正文色，悬停加下划线，`aria-haspopup="dialog"`、`aria-expanded`），是卡片上唯一的时间：这张卡的计时进行中或暂停时，它显示已存记录加这一段的时间，如“35:12”，每秒只更新自己，卡片和列表不重绘；否则按整分钟显示。它的可访问名称是“已用 35m （标题）”／`35m logged (title)`。原来另外的经过时间输出已经去掉。Start 带上任务的领域（自己的，否则父任务的；未分类为空），这段计时存成记录时保留它。运行后状态写“正在做／Now”，按钮为 Pause、Stop；暂停后写“已暂停／Paused”，按钮为 Resume、Stop；第一张写“下一步／Up next”。Stop 保存计时但不完成任务：满一分钟的一段按整分钟存为一条记录；番茄钟到时由页面发出 Finish，最多记到目标时长；正计时最多记 4 小时，页面的计时也停在 4 小时。全局计时条（标题、时钟、暂停／继续、结束和完成，最后是“小窗计时”，见下）不变，正计时时它的时钟向上数；它按计划内容列居中，侧栏收起或调宽后仍居中。完成是一次 Tasks 写入：同一批里把这一天队列中的步骤标为已完成，与这个任务或其后代有关的进行中或暂停的计时按它自己的那天存为记录并停止。

**用时记录**（`src/FocusEntries.tsx`）：点“已用”在卡片内容列的左缘、这一行下方打开一个浮层（`position: absolute`，宽 300px、最宽为窗口减 32px，最高 320px、自己滚动，圆角 7，二级阴影），卡片和列表不移动。窄屏上右边放不下时，它在绘制前向左移，始终留在窗口内，页面不横向滚动。它不是模态的：打开时焦点进入浮层，Tab 可以在里面移动，也可以移出；焦点离开、点击外面或 Esc 关闭它，用关闭按钮或 Esc 关闭时焦点回到“已用”。标题是“用时记录 · Draft API”（13px 半粗）和关闭 ✕。每条记录一行：计时那一段的开始时间（账户时区，`HH:mm`），手动添加的写“—”，所以不另写来源；56px 的整分钟输入框（1–1440，名为“分钟，09:40”或“分钟，手动”）；删除按钮“删除记录”。下方是“合计 40m”和“+ 添加时间”，后者打开一行“[15] 分钟 [添加]”，默认 15，回车添加。输入框回车或离开时若有改动就保存，0 不接受（删掉时间用删除）；Esc 先恢复输入框，再按一次关闭浮层。删除立即执行，不再确认，需要时可以再加回来。写入都经过 App 的同一个写入队列，先确认再显示：这一行显示等待标记（`pendingEntry(id)`），确认的记录直接合并，不重新读取；失败时用 App 的错误条，输入框回到已保存的值。读屏会听到“已保存”或“已删除”。手动添加时间的领域：Plan 列出这个任务时用它的领域；否则用它最近一条记录的领域；再否则用 Plan 列出的父任务（`FocusTask.parent_id`）的领域；都没有则为空。浮层带 `data-no-drag`，在里面按下移动不会拖动卡片。没有记录时写“还没有记录。”。

**其他日期**：同样的列表，只读：没有开始、完成、拖动和计时方式，“调整计划”保留。今天和过去的日子仍可以打开记录浮层，修改或添加时间；将来的日子没有可记的时间，卡片下方只写估时。这一天没有步骤时写“这一天没有安排步骤。”。“已完成”勾选同样适用。

**其他用时**：记录留在记下它的那一天，步骤之后离开这一天的队列（在 Week 里移到别的日子，或移出日期）时，这一天的“已用”仍算它。今天和过去的日子在队列（勾选时还有“已完成”）下方另起一条同样的分隔标签“其他用时”／`Other time`，列出这些步骤，只读，内容 0.72 不透明，没有删除线，标题来自 Tasks 的 Focus 读取；它们的“已用”同样打开记录浮层。所以摘要的已用等于各卡之和，每条记录都能修改。

**已完成**（2026-10-19 owner 决定）：标题栏刷新按钮前有一个小勾选框“已完成”／`Completed`，样式同任务列表的那个（11px，muted），只在“日”出现，一直显示，每次进入 Focus 都不勾选，也不记住。勾选后，未完成的队列下方是一条 12px muted 的分隔标签“已完成”，再是这一天队列里已完成的步骤，按队列顺序，在它们自己的列表里，不在可排序的队列中。它们有同样的领域色条，内容 0.72 不透明，标题 muted 加删除线；勾选框是填满强调色的圆加勾，只是图示（“已完成”）；下方仍是“预计 30m · 已用 35m”，今天和过去的日子可以打开记录。没有开始，没有拖动；标题打开 Tasks 自己的任务对话框，在那里可以重新打开它（规划面板需要未完成的任务）。标题和估时来自 Tasks 的 Focus 读取（`FocusState.tasks`、`readFocus` 的 `tasks`），不会显示“任务暂不可用”。原来的“今天已完成 N 项”一行已经去掉。

**周和月统计**：[Tasks GTD](../../../tasks/docs/gtd.md) 提供周柱状图、月日历、已记录时间和按任务分组的报告，代码在宿主的 `tasks/web/src/gtd/`。统计按服务端报告读取，不在本包重复计算；点击过去或今天的日期打开 Focus，编辑当天的记录。未来日期和月历里不属于当前月的格子不能打开。

**读取**：今天使用页面自己的 Focus 数据，其他日期通过 `readFocus(date)` 读取，Focus 打开期间按日期缓存在组件里。每次写入确认后（App 的写入计数加一），重新读取当前显示的日期；记录写入还会立即合并进所有缓存日期。读取下一天时，上一天的内容留在原处，变淡（0.6）、不可操作并带 `aria-busy`；首次读取时显示一行 muted 的加载文字。失败时显示内联错误和“刷新”按钮。

旧日期的活动计时不冒充今天同名 ID 的活动计时，也不允许今天另启一段覆盖它。全局计时条在 Plan／Focus 切换时保留，不新增浏览器本地计时存储。

**小窗计时**（2026-10-20 owner 决定，“极致优雅美观，市场上的太俗”；外观由单独的设计阶段定稿，按它逐像素实现）：计时条最后一个安静的图标按钮“小窗计时”／`Mini timer`（lucide `PictureInPicture2` 17px，平时 muted，悬停同其他图标，窗口打开时 `aria-pressed="true"` 并变为强调色；再按一次关闭）。只在浏览器有 Document Picture-in-Picture（Chrome 116+）时出现；请求被拒绝时什么也不发生。点击时请求 320 × 120 的窗口，之后 Chrome 沿用 owner 拖到的大小和位置；64px 高时仍显示步骤标题和操作；更高的窗口同时显示所属事项和用时比例。窗口里只有一份样式（`src/mini-timer.css`，以文本导入），以及从页面 `.plus-root` 复制的九个计算后的 `--plus-*` 颜色和字体，所以宿主的覆盖同样生效，不复制应用的样式表；没有深色模式。

内容（`src/MiniTimer.tsx`）：沿用白底、原有强调色、领域色和字体。步骤标题与当前会话始终可见；有空间时显示所属事项，标题可折两行。时钟用等宽数字、500 字重，显示 `mm:ss`，满一小时显示 `h:mm:ss`；番茄钟显示剩余时间。右侧 Pause／Resume、Stop 和 Complete 使用现有 Lucide 图标，平时即可操作，有悬浮文字和键盘焦点轮廓，不再等待 hover。Complete 仅在 Plan 列出这个任务时出现。

底部 3px 进度条显示当日记录加本段用时对估时，旁边写 `12m / 45m`；64px 高时比例移到标题右边。到 90% 时标出剩余分钟，超时仍沿用警示色与超时分钟；没有估时就显示“未估时”，不画空进度条。番茄钟的进度按本段已过时间和目标时长。暂停时时钟变淡，状态写“已暂停”。写入期间按钮停用；失败时进度位置显示“没有保存。请回到主窗口查看。”，完整错误仍在主窗口。只有小窗组件每秒更新，渲染不增加请求；减少动态效果时关闭进度条过渡。截图与本轮检查范围见 [Tasks UI review](../../../tasks/docs/ui-refinement.md)。

三个按钮调用计时条自己的函数（`commandTimer`、`complete`），经过同一个写入队列，没有第二套计时状态，也不在浏览器里保存任何东西。时钟用小窗自己的定时器，在会话的下一个整秒刷新：主窗口隐藏或最小化时它的定时器会变慢，而那正是看小窗的时候。60 秒一次的计时读取在只有小窗可见时也照常进行，小窗获得焦点时也读取一次。会话结束（结束、番茄钟到时、完成被确认，或读取显示没有计时）、owner 关掉它、Plan／Focus 卸载时，窗口立即关闭，按钮回到未按下。

**后台模式**：会话存在时，宿主让 Plan／Focus 在其他页面后面保持挂载（`onSession` 报告会话的有无，`background` 表示宿主在显示别的页面），所以去 Today、Mail 或项目时小窗留着、按钮照常工作。后台时 App 只渲染小窗（React 树中位置不变，不会重新挂载），以及离开的问题等待回答时的计时条；保留数据、写入队列、计时读取、番茄钟的结束和离开时暂停。别处的任务写入（`refreshRevision`）立即读一次计时，因为在别处完成或删除这一步（或它的父任务）会结束会话；小窗打开时改为完整读取，让它的完成带上任务当前的 etag。其他完整读取（回到窗口）等到 Plan／Focus 再显示：若错过了别处的写入就读一次，并在读完前停用写入，否则数据超过一分钟才读。在后台挂载、还没有任何数据时（宿主为离开时暂停找到了会话），先完整读取一次。没有会话时什么都不挂载；有会话时代价是窗口可见时每分钟一次 GetFocusTimer，以及别处每次任务写入一次。后台的失败在别的页面上什么也不显示，打开 Plan 或 Focus 时重置。

**离开时暂停**（2026-10-20 owner 决定）：Focus › 日（今天）的计时方式后面一个安静的勾选框“离开时暂停”／`Pause when away`，样式同页头的“已完成”，悬停说明“正计时在锁屏或 10 分钟无操作时暂停，回来时问你是否计入。”。只在浏览器有 Idle Detection API（Chrome 94+）且宿主保存这个设置（`idlePause`、`onIdlePause`）时出现。设置属于这台设备，Tasks 存在 localStorage 的 `tasks.idle-pause`（`on`，没有即关），不是计时状态。观察在挂载 App 的窗口里进行：设置打开时，Tasks 在别的页面上加载和每次回到窗口时读一次计时，有会话就在页面后面挂载 App（`background`），所以刷新、重新打开应用或在别的设备上开始会话后，在 Today 等页面上也照常观察。权限只在勾选的点击里请求（`IdleDetector.requestPermission()`）；被拒时保持未勾选，后面跟一行 muted 的“浏览器没有允许检测离开。”，直到下一次点击；取消勾选不需要权限。只有设置打开且权限为 granted 时显示勾选：权限被收回就显示未勾选，再点会重新请求。

只管正计时，番茄钟不变。离开的起点：锁屏时为锁屏那一刻；`t` 时报告 10 分钟无操作为 `t − 10 分钟`；主窗口每 15 秒一次心跳，任何事件距上次心跳满 10 分钟（机器睡眠或页面被冻结）为上次心跳；几种同时出现取最早的。开始观察时（以及回答后继续时）看到的状态只是基线：若是无操作或锁屏，要先看到一次有操作且未锁屏才会暂停（检测器启动时报告的是这台机器真实的输入状态，闲置的 Mac 上为无操作，CI runner 上为有操作；从手机开始的会话不能因为 Mac 正闲着就被丢弃）。发现离开时立即在 Tasks 里暂停在离开的起点（CommandFocusTimer PAUSE 带 `effective_time`），别的窗口和设备都看到已暂停；若 owner 不再回到这个窗口，离开的时间就不计。

回来（有操作且未锁屏）时，计时条的状态行让位给问题“离开了 N 分钟，要计入吗？”／`Away for N min — count it?`（正文色；N 为回来时刻减 Tasks 的 `pause_time`，四舍五入到分钟，至少 1）：问题在条内单独占一行，在标题、时间和按钮那一行的上方，不换行，所以窗口再窄也只有标题让出宽度；暂停／继续的位置换成“计入”／`Keep` 与“不计入”／`Discard` 两个文字按钮（13px、500、强调色，悬停出现下划线，基线与时间对齐）；结束和完成仍可用，它们结束这段已暂停的会话，离开的时间不计。这一步在 Focus 的卡片上，继续的位置同样换成“计入”和“不计入”（可访问名称 `Keep: 标题`、`Discard: 标题`），结束保留，所以计时条、卡片和小窗给出同一组回答。小窗里问题占步骤标题那一行，两个回答占控件的位置（见小窗的设计定稿）。计入：RESUME 带 `effective_time = pause_time`，就像从没暂停过；不计入：RESUME 不带时间，从现在继续。问题出现时以及回答确认后（“已计入离开的时间。”／`Away time counted.` 或“已从现在继续。”／`Resumed from now.`），App 一直存在的 `role="status"` 区域朗读一次。问题属于那一次暂停：计时在别处有任何改变（新的 etag）就收起；刷新或关闭窗口也收起（不在浏览器保存），计时保持暂停，继续即从现在算。问题等待时再次离开不发送任何东西：问题收起，离开期间计时条和小窗显示已暂停，下次回来时再问，分钟数算到这次回来（已发出的回答照常等它的确认）。关掉设置时已做的暂停保留，问题立即出现。

判断是纯函数 `src/idle-pause.ts`（off、arming、watching、pausing、away、asking 六个阶段，每个事件带时间，测试用假时钟）；`src/useIdlePause.ts` 接到浏览器上：设置打开、权限 granted、这个窗口持有观察，且有正计时在跑或被它暂停时，运行一个 `IdleDetector`（`threshold: 600000` 和 `signal`），否则中止；心跳；Web Lock `tasks.idle-pause` 让两个 Tasks 窗口只有一个观察（排队等待，前一个窗口关闭后接手；没有 `navigator.locks` 时照常观察）。命令经过 App 的同一个写入队列，执行时才读最新确认的计时（写入确认时立即更新，不等 React 渲染，所以排在一次计时写入后面的暂停带着那次写入返回的 etag）。暂停失败时第一次照常显示错误；之后每次心跳用同一个起点安静重试（同一个 request ID，丢失的回答会被重放），直到会话不再是正计时；读到计时恰好暂停在这个起点，就是自己那次暂停。精确度：Chrome 何时报告无操作和锁屏由它决定，起点可能晚一点（算作工作）；睡眠的误差在一次心跳之内（隐藏窗口最多一分钟）；暂停与继续按整秒，与其他暂停一样；服务端把时间限制在合法范围内。

## 写入与读取

任务详情只为用户编辑过的规划范围、领域、截止日期和提前量保留局部草稿；其余字段随任务刷新。草稿对应字段在别处改变时，先提示“保留我的修改／使用最新值”，保存暂不可用；保留仅接受当前值作为新的比较基线，仍要再点保存。规划写入只提交改变的字段，截止日期写入沿用现有接口并保留最新未编辑提前量。估时与新增步骤沿用原流程。

2026-10-15 owner 批准：拖动先显示、按序保存，只对下列拖动与移出放宽“写入期间禁用写入控件”。

- Review 跨列拖动和列内排序、Week 承诺排序、Week 拖入日期、“下一步”排序、跨日移动和同日排序落下后，卡片立即显示在预期位置。只有这张卡等待：变暗、小转圈、不可拖动，移出按钮隐藏。其他卡片、切周和下一次拖动照常可用。
- 等待确认的卡片在可访问名称中带“正在更新…”；抓手用 `aria-disabled` 停用但保持可聚焦，键盘落下后焦点留在移动的卡片上。减少动态效果时小转圈停止，只保留变暗。
- 等待确认的 Review 卡仍带拖动前的 etag：它的详情在确认或撤回前只读，详情标题显示同一等待标记；结束后显示服务端保留的规划范围。本周目标与任务无关，拖动期间照常可编辑。
- “移出日期”不提前删除：卡片原位等待，Tasks 确认后才消失。
- 所有写入进入同一个先进先出队列，按操作顺序执行。每次加入、移出、同日排序或跨日移动是一次 MoveFocusStep，只改这一个步骤，不写回屏幕上可能过时的整条队列；其他标签页刚加入的步骤和排在前面的移出都会保留。插到某步骤之前而它已不在那天时，Tasks 拒绝（“This step has moved. Refresh and try again.”）。每天最多 20 个步骤。任务写入带 Plan 持有的 etag，不先读取：每次确认的任务写入（规划、依赖、排序、估时）都返回新的 etag；过时时 Tasks 拒绝，撤回后重新读取。确认后换成服务端返回的任务或队列（队列替换，那天的用时记录保留）。
- 队列、计时和用时记录的写入各保留一个请求 ID，直到确认；回答丢失后的同样重试按原请求重放，不会写两次。
- 任一写入失败时，排在其后的写入不再发送，所有等待确认的预期变化撤回；原有错误区域说明“更改未保存，已恢复”、实际失败和其后未发送的更改数，队列空闲后重新读取。等待确认的卡片不显示为已保存。
- 邮件归类的保存只写 Tasks，在对话框里等待和报错。
- Week 的“添加步骤”（下一步托盘的一格输入）也先确认，但不打断打字：回车后标题先作为等待卡显示，输入框清空并保持打开，读取列出新步骤后换成步骤卡；一次只保存一个。
- 完成、在任务详情添加小步骤、任务详情里的估时下拉框、提前开始、标为进行中（含看板卡片的“开始”）、详情中的规划保存、添加或移除依赖、本周目标、加入今天、计时以及周回顾中的移到本月、留到下周和完成回顾仍先确认，写入期间停用写入控件；本周目标和“沿用”只用 `aria-disabled` 标为不可用，保留焦点（见[本周目标](#本周目标)）。

读取不锁定看板，也不重复读取写入已返回的结果：

- 打开、刷新按钮、返回标签页（距上次完整读取至少 60 秒）和写入后需要的读取都在后台进行，只转动标题栏刷新图标。刷新按钮带 `plus-refresh` 类，宿主可以用 CSS 把它移进自己的窗口标题栏（Tasks 隐藏 Chrome 标题栏时），组件和行为不变。与写入重叠的读取作废，队列空闲后再读，旧读取不会覆盖较新的确认结果；两次读取重叠时，先发出的读取晚到也不覆盖后发出的结果。
- 规划写入（UpdateTask，含标为进行中、提前开始和依赖）返回的任务、UpdateWeeklyBet 返回的目标、确认后的日期队列和估时保存后的时长直接合并，不再读七天；目标别处改过时只重读一次 GetPlan。
- 完成任务后仍重新读取，不在本地删除：Tasks 完成循环任务时会推进到下一次。读取完成前该步骤等待，不能再次完成。
- 离开 Plan／Focus 时，上次确认的数据只留在当前页面内存中；返回时立即显示，再后台读取。它可能早于一次完成或跨过午夜，所以本次读取完成前不开放写入；这次读取失败时只显示错误，并丢弃这份内存数据。离开时显示本周的，返回后跟随服务端的当前周（含周日轮换）。
- 加入日期和跨日移动直接写 Tasks 的队列：队列里只能放 Tasks 中存在的未完成任务，不需要同步。估时就是 Tasks 的时长，由宿主写入（`updateEstimate`）。

### 整行拖动

2026-10-19 owner 决定：Plan 的卡片（Review 各列、Week 的承诺、下一步、快速事项和日历里的步骤）和 Focus 今天的步骤像任务列表的行一样按整行拖动，用同一套设置（`src/row-drag.ts`，与 Tasks 的 `TaskDrag.tsx` 相同）：在卡片任何地方按下，鼠标移动 6px 后开始拖动；触屏上按住 250ms 才开始，按下就滑动时页面照常滚动。所以单击和双击从不开始拖动。完成勾选框、“开始”和“移出日期”按下后再移动也不拖动，标了 `data-no-drag` 的部分同样不会；写入期间、等待确认或正在计时的卡不能拖。

- 可拖的行显示抓取光标，标题按钮沿用它；原卡变淡到 0.3，浮层保留阴影；插入线是任务列表的 2px 强调色线。排序落下后卡片滑到预期位置（dnd-kit 的 250ms，减少动态效果时没有）。
- 抓手仍在，给键盘拖动、读屏说明和落下后的焦点用。事项卡（Review 和 Week 的承诺）的 17px 抓手一直显示，在卡片左边 25px 的内边距里。下一步、快速事项和日历卡的 14px 抓手只在悬停这张卡或键盘焦点落在它上时出现，标题不移动；触屏没有悬停，不显示它们。只有抓手设 `touch-action: none`，手机上卡片的行仍可滚动。
- Focus 只有今天的“日”可以排序（`src/FocusView.tsx`，同一套 `planningSensors`）：未完成的步骤是一个可排序列表，落下后是那一天里的一次 MoveFocusStep，插到落点那一步之前（放到最后时没有），立即显示在新位置并等待确认；读屏说“第 N 项”，键盘落下后焦点留在它的抓手上。抓手是卡片左边内边距里 12px 的叠加按钮“移动步骤：标题”，同样只在悬停或键盘焦点时出现，按住它拖动也可以；不能用时（写入期间、正在计时）它平时仍隐藏，悬停时才变淡显示。拖动的浮层与这一行同宽，留在指针下。正在计时或等待写入的卡不能拖；别的日子和“已完成”列表不在可排序列表里，记录浮层里按下也不会拖动。
- 没有引入任务列表的 `TaskDragProvider` 和它等待写入的 `suspend()`：Plan 和 Focus 仍用自己的写入队列和预期显示，慢的写入不会挡住下一次拖动。

| 拖入／移出搁置       | UpdateTask，mask `planning_flags`：新加 `parked` 时 Tasks 去掉规划范围和 `active`                | 保存的任务，合并单任务                                |

| 保存、清空、沿用目标 | UpdateWeeklyBet：`weeklyBets/{周一}-{work\|personal}` 的 `text` 和 etag，只写 D1，不写任务       | 返回的 WeeklyBet 直接合并；冲突时重读一次 GetPlan     |
| 删除小步骤           | DeleteTask，Plan 持有的 etag 与固定 request ID | 确认后关闭面板，后台重新读取任务和 Focus |
| 创建小步骤           | 每个步骤一次 CreateTask（`kind=step`、`duration_minutes`）                                       | 新步骤的 ID（按输入顺序），后台再读取                 |
| 切周                 | ListFocusDays（七天，一次）                                                                      | 那周的队列与记录、它们提到的任务（并入 `FocusState.tasks`） |
| 同日队列、跨日移动、Focus 排序 | MoveFocusStep：源日、目标日和插在它之前的步骤                                          | 改变的日期的队列，直接合并（记录保留）                |
| 移出日期／加入今天   | MoveFocusStep：只有源日，或只有目标日                                                            | 该日的队列，直接合并                                  |
| Focus 的其他日期     | `readFocus(date)`：ListFocusDays，只读一天；写入确认后重读显示的日期                 | 当天的队列与记录、它们提到的任务、Tasks 的今天        |
| 用时记录             | CreateFocusEntry、UpdateFocusEntry（只改 `seconds`，带 etag）、DeleteFocusEntry                  | 保存或删除的记录，直接合并                            |
| 估时                 | 宿主的 `updateEstimate`：Tasks UpdateTask 的 `duration_minutes`，带 Plan 持有的 etag             | 保存的时长和新的 etag（`{ estimate, etag }`），直接合并；零表示清空 |
| 计时                 | CommandFocusTimer，etag 与稳定 request ID；Start 带番茄钟时长和领域；离开时暂停的 PAUSE／RESUME 带 `effective_time`（Tasks 把它限制在本段开始或 `pause_time` 到现在之间） | FocusTimer 映射为 TimerSnapshot（`pause_time` 映射为精确到毫秒的 `pausedAt`），保存的记录一并合并；idle 清除显示状态 |
| 真正完成（Focus 与 Plan 的勾选框） | 宿主的 `completeTask`：Tasks CompleteTask（Plan 持有的 etag）带 `focus_day`，日历卡片带所在日期，其余带 Focus 的日期 | Tasks 确认后后台重新读取，不靠本地删除                |
| 提前开始             | UpdateTask，mask `deadline,lead_days`；没有截止日期时 Tasks 存 0                                 | 保存的任务（Deadline、leadDays），Due 保留            |
| 周回顾数据           | 加载的任务、队列和 GetPlan（下周选择 ID、上周至下周的目标）；清单打开时 GetWeeklyReview（待理清的邮件数、回顾任务） | 回顾的两项到达前显示“—” |
| 依赖                 | 每个任务的 `dependencies`（所等任务的 ID、标题和 `done`），与加载一同读取                         | 由任务得出的全部依赖                                  |
| 添加／移除依赖       | UpdateTask（mask `dependencies`，这个任务新的整组依赖，Plan 持有的 etag）；再选已满足的循环任务时先移除再加入，两次 | 保存的任务和它的依赖，直接合并                        |
| 移到本月／留到下周   | UpdateTask，mask `stage`（monthly／committed）                                                   | 保存的任务，合并单任务                                |
| 完成回顾             | CompleteTask，不带 `focus_day`（Tasks 的今天）                                                   | Tasks 确认后后台重新读取                              |
| 邮件归类             | GetMailCategories、UpdateMailCategories（Tasks，整组替换，只写 D1，可为空）                      | 保存后的归类和 etag                                   |

初次读取并行获取独立数据；切周只读七天队列。App 合并确认的任务、队列和计时响应，原有读取序号保护正在查看的周，Plan／Focus 切换不扫描所有任务。离开 Plan／Focus 后返回时先显示内存中的上次确认数据，再后台重新读取；读取完成前不开放写入。有 Focus 会话时页面在后台保持挂载（见[小窗计时](#focus-与计时)），回来时只在错过了读取或数据超过一分钟时重新读取。宿主提供一个传输：所有方法都发到同源的 `/api/tasks/v1/*`（2026-10-21 起；之前周回顾的两项和邮件归类经 `/api/plus/v1/*` 由 Todofy 的 Planning 通道转发）。
