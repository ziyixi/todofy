# Todoist Plus 设计

扩展负责 Todoist 中的界面和显式用户操作。Todoist 保存任务、父子关系、标签、计划日期与 Deadline；Todofy 是唯一 Todoist 写入者，保存标签映射、周重置、操作去重和任务之间的依赖；FlowDay 保存按日队列、手动估时和计时记录。详细布局和交互合同见[界面与接口说明](planning-interface.md)。

## 三种规划含义

本周目标、规划范围和具体日期分别使用已有的数据：

| 含义                            | 保存位置              | 用户操作                        |
| ------------------------------- | --------------------- | ------------------------------- |
| 工作／生活的本周整体目标        | Todoist 的 Bets 标签  | 选择一个现有任务，调整 Bet 标记 |
| Quarter／Month／Week／Committed | 对应列的 Todoist 标签 | Review 拖动或任务详情调整范围   |
| 某天执行的小步骤及顺序          | FlowDay 的按日队列    | Week 拖动小步骤、移出日期       |

Bet 独立于规划范围。已有多个或未分类 Bet 保留并提示，由用户调整。切换到未来周只读取那周的队列；上方目标和承诺仍属于当前账户周。

## 界面

WXT + React 的三个 Shadow DOM 挂载点提供侧边导航、Plan/Focus 主内容和原生任务详情的“步骤与时间”。字体和颜色读取 Todoist 当前浅色主题的 token，主题切换只经 CSS 生效；Plus 没有深色模式，见[主题](planning-interface.md#主题)。焦点框有意使用文字强调色 `actionable-tertiary-idle-tint`，不用 Todoist 的 `actionable-focus-tint`：前者在八个公开浅色主题中与背景至少 4.5:1，后者在 Tangerine 约 2.9:1，低于非文字元素的 3:1；Todoist 自身焦点框实际用哪种颜色待真实页面核对。DOM 用于挂载、取得真实 task ID 和暂时隐藏已替代项，选择器集中在 `src/anchors.ts`；替代界面未挂载时不隐藏原生项，见[恢复](planning-interface.md#恢复)。业务数据使用根 proto 的类型化 API。任务身份不依赖标题或 Todoist 的 React 内部状态。

Plan 顶部是 Work／Personal 两组本周目标。Review 从左到右是“该开始”“等待中”（都只在有卡片时出现）和四个规划列，每个任务只在一列；各列用同一种紧凑的事项卡，优先显示任务标题，下面显示工作／生活上下文、步骤数和已排程数，该开始或在等的卡片换成一句状态。优先级使用 Todoist 原值。Week 展示本周承诺总览（同一种卡，始终显示步骤和排程数），选中一个事项后出现其小步骤，再把步骤安排到具体日期。

卡片的所属事项由 `planning-outcomes.ts` 推导。没有独立规划范围的中间子任务提供层级上下文；显式使用不同范围的子任务按其自身规划显示，不批量改写后代标签。色标从所选事项的 ID 派生，避免一个宽泛祖先使所有承诺同色。完整祖先路径保留在 tooltip 和任务详情中。

拖动复用 `@dnd-kit/react` 0.3.2。Review 只调整事项范围；Week 只调整 FlowDay 队列。抓手与标题点击分开，预览和投放提示使用同一套组件样式，落下动画为 160ms。日期看板按可用宽度显示七日、三日或单日，保留日期选择按钮，避免横向滚动。

Focus 固定显示今天的执行队列。卡片先显示步骤标题，再显示所属事项和估时，计时按钮显示 Start、Pause、Resume、Stop。停止和暂停不完成任务；完成是单独操作。FlowDay 本地任务和杂项保持可见，并提供原 FlowDay 页面入口。

全局计时条在 Plan／Focus 切换中保留。运行或暂停的步骤不能拖走或移出原日期；旧日期的计时保持原 flow day。所有数量上限及超过两小时的步骤都只提示。

## 标签与周重置

“计划标签”从 ReadPlan 返回的当前 Todoist 标签中选择精确 ID。Month、Week、Committed 必须分别绑定不同标签；Quarter 可以暂不使用。保存调用 UpdatePlanLabels，只更改映射，不搬动已有任务。领域、Bets、提前开始标签继续采用既有映射；不能把同一标签 ID 同时用于其他角色。

账户本地周结束后，已有周重置流程把记录的未完成承诺放回周候选，并移除旧 Bet。它不升级月／季度候选，也不移动 FlowDay 的日期队列。浏览历史或未来日历不触发标签重置。周日在 Plus 中设为承诺或 Bet 的任务记为下周的选择，这次重置保留它；记录不会被当天的扫描或其他写入改回旧周。

Must Start 的 `deadline before` 使用严格上界。提前 N 天标签的实际窗口从 Deadline − (N−1) 天开始；界面显示同一个日期，不改变既有筛选规则。`lead_1m` 沿用 30 天。任务详情修改真实 Deadline 与提前窗口，保留计划日期。

## 截止日期

截止日期按一条生命周期看：截止日期 → 启动窗口 → 进行中 → 完成。Todofy 的 `must_start`、`missing_lead` 规则不变；`src/deadlines.ts` 在完整读取后据此和字面标签 `active`、`blocked`、`parked` 给每个任务一个状态。启动窗口打开（截止日期前 N 天）或已过截止、又不是进行中的任务出现在 Review 最左的“该开始”，有自己规划标签的留在原列并写明状态；窗口打开前不出现。确认就是把卡片拖入某个规划列（规划标签和 `active` 一次写入），或用卡片悬停时的“开始”只加 `active`；之后它不再是该开始。没设提前量只在周回顾占一行；Focus 只在该开始的事这周还没安排时显示一行文字；任务详情的截止日期段说明当前状态。“标为进行中”和“开始”都是 SetTaskPlan 的 `active` 字段，只增删账户已有的 `active` 标签，Plus 不改 Due 或 Deadline，也不创建标签。界面不加新页面、标签页、图标、徽章或颜色，看板和日历下方不叠放列表，只有“已过 N 天”用 `--plus-danger`；“开始”平时不占位置，只在悬停或键盘焦点时出现在标题第一行右端，不挪动布局。原生行标记不在这一版。

## 依赖

一个任务可以等其他任务完成（2026-10-16 owner 定稿）。依赖只存在 Todofy 的规划库里，是两个 Todofy 任务 ID 之间的边，对外仍用 Todoist 任务 ID；不写 Todoist 的标题、描述、评论或标签，也不镜像 `@blocked`，所以只有装了 Plus 的桌面 Chrome 看得到。`src/dependencies.ts` 在完整读取之后推导：所等的任务在活动列表里就在等，不在就算满足；循环任务以 Todoist 的 `completed_count` 为准，建立依赖之后的下一次完成算满足。满足只改变显示，不改日期或标签。任务详情有“依赖”段和内联的即时搜索选择框，会形成循环的任务灰色并写明原因；在等而没有自己规划标签的任务进“等待中”，卡片的那一句状态写 `等「B」`。已满足的依赖不构成环、不占 5 项，给新依赖让位，也可在详情里移除；已满足的循环任务可以再选一次，等它的下一次完成。Review 看板显示完整读取后让 Todofy 核对读取里消失的任务，区分完成、删除和说不出的情况；因此不再等待的任务在看板各列下方提示一次，Focus 和 Week 不核对，不会用掉这次提示。见[依赖](planning-interface.md#依赖)和 [Todofy 文档](../../todofy/docs/todoist-plus.md#dependencies)。

## API 与状态更新

独立扩展口令保存在 background 的 trusted local storage；网页 content script 只能提交有限操作，不能读出口令。连接使用 hooks API 和 FlowDay service binding；owner 设置沿用 Access、Origin、CSRF。扩展不保存 Todoist API key。

单任务规划写入采用 SetTaskPlan 的确认任务；提前开始采用 SetTaskLead 的确认任务；排程采用 UpdateFlow／RolloverFlow 的确认队列；计时采用 CommandTimer 的确认 TimerSession。界面收到确认后更新相应状态，任务完成、批量步骤创建、估时和标签映射随后在后台重新读取完整状态。选择目标涉及两个显式 Bet 写入，合并两项确认结果；没有独立目标数据库或 RPC。

同日排序用 UpdateFlow，跨日用 RolloverFlow 后在目标插入位置保存。队列保留全部 ID、本地任务和完成记录；同日不调用 RolloverFlow。新建子任务尚未进入 FlowDay 时，安排或设置估时前进行既有有界同步；同步成功后记住这些任务 ID，并只把 ID 存入 session storage，后台 worker 重启后不在 FlowDay 的 30 秒节流内重复同步。

所有写入经同一个先进先出队列按顺序执行。Review 跨列和 Week 日期拖动先显示预期位置，只把该卡标为等待；移出日期的卡片原位等待。UpdateFlow 没有 etag，移出日期和加入今天执行时先读取 FlowDay 当前队列，只增删这一项。失败时撤回全部等待中的变化、丢弃其后排队的写入并重新读取。其他写入先确认，期间停用写入控件；新标签映射改变全部任务 etag，后台重读完成前也停用。读取在后台进行，不停用看板；与写入重叠的读取作废后重读，先发出的读取不覆盖后发出的结果。

Plan／Focus 直接切换使用已读数据；离开扩展到原生页面后再返回，先显示当前页面内存中的上次确认数据，再后台重新读取，读取完成前不开放写入，不持久保存任务内容。返回标签页时，距上次完整读取满一分钟才重新读取。初次加载中账户和任务查询并行。选周只读七天队列；完整加载未来周时另保留今天队列。同一个读取序号阻止迟到结果覆盖当前周。计时 UI 仅按确认 timestamps 显示经过时间，停止响应明确清空计时状态。

任务完成、步骤创建和计时沿用稳定 request ID，计时同时检查 etag。失败不乐观移除任务；冲突后刷新实际状态。手动清空估时显示“未估时”，同步不恢复旧 Todoist duration。

## 等待与周回顾

两者都只用已读取的数据：任务的 `update_time`（Todoist 最后修改时间）、标签和截止日期，加上 ReadPlan 返回的邮件项目、回顾任务和下周选择 ID。“等待中”是看板的一列，按字面标签 `waiting`、`blocked` 显示“N 天未变动”和截止日期，在等另一个任务的写 `等「B」`，拖入规划列只写规划范围；“将来／也许”按 `parked`、`onhold`。每个操作都是已有的单任务写入（SetTaskPlan、SetTaskLead、CompleteTask），只在点击时执行；不移除标签、不自动安排、不调用模型，也没有新的 D1 表。勾选状态按 ISO 周只存于本浏览器。Week 的承诺未安排提示是一行文字，不加逐卡标记。

## 原生页面与发布

连接与映射确认后，扩展按精确 ID 隐藏被替代的筛选器和规划标签。哪些筛选器算被替代由 Todofy 按规范化查询认定，并由一致性测试守住：原查询会列出的每个合成任务都必须在 Review 看板上（“该开始”“等待中”，或在自己的规划列写明状态）、已是进行中，或（没设提前量的查询）在周回顾那一行。原生页面只调用 ReadPlan；background 在 storage.local 保存只含 ID 的配置，下次加载 Todoist 时立即按它整理侧栏。其他筛选器／标签收藏（如 Quick 和 `@parked` 的筛选器）在原位置收折进 Other views，它的开合是 storage.local 的一个布尔值，断开连接时清除；项目收藏保留；账户收藏对象不改。原生任务详情替代技术标签显示时，office／home 等领域标签继续显示。

更新使用同一固定目录，先重新加载扩展，再刷新已打开的 Todoist 页面。旧注册脚本与新 CSS 可能混在同一页面，普通网页刷新不能代替扩展重新加载。停用或重新加载扩展后，回到已打开的 Todoist 标签页即恢复原生界面，无需刷新。扩展设置页的“Todoist 页面检测”一行说明最近一次页面检查是否全部正常，或哪项增强已关闭及原因，见[页面检测](planning-interface.md#页面检测)。

生产构建、CI、发布及真实账户验收分别记录。公开代码与截图只使用合成任务、标签和测试凭据；不包含个人任务或真实账户截图。
