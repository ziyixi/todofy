# 投递 Dashboard 的统计口径

Dashboard 使用现有 Cloudflare Access owner 身份访问 Mail Hero API，读取 D1 中的 webhook 投递尝试记录；不读取邮件正文，也不引入图表服务或新的付费产品。

`GET /api/v1/delivery-stats?from=<ISO-8601>&to=<ISO-8601>&bucket=hour|day` 使用 UTC 半开区间 `[from, to)`，以尝试的 `finished_at` 归入小时或日期。小时桶最多查询 7 天，日期桶最多查询 90 天；自选日期按 UTC 日（包含选中的结束日期）转换成半开区间。返回四个互斥计数 `succeeded`、`retried`、`failed`、`unknown`，以及同口径的时间桶。没有实际发出请求的 `not_sent`、尚未结束的尝试和投递创建前即失败的事件不计入该图。列表中的一条事件可以有多次尝试，因此 Dashboard 的尝试数不等于邮件数或事件数。

| Dashboard 文案 | 已完成尝试的结果 | 含义 |
| --- | --- | --- |
| 成功 | `delivered` | 目标返回 2xx，按 webhook 合同表示消费者已持久接管；不表示 Todofy 后续业务成功。 |
| 重试 | `retryable` | 本次请求暂时失败，并已进入自动重试队列。一次事件可能贡献多次。 |
| 失败 | `rejected`、`failed` | 本次请求后自动投递终止，包括不可重试响应，以及重试预算或窗口在本次请求后耗尽。手动重试仍可产生后续尝试。 |
| 未确认 | `interrupted` | 请求结果无法确认，不能据此声称成功或失败。 |

旧版本把一些已经耗尽重试预算的暂时性错误也写作 `retryable`。历史记录保持原样，不能凭事件的**当前**状态倒推过去那次请求的结局；因此旧数据中的“重试”可能包含这种终止尝试。新版本写入时直接记录本次尝试的终止结果。

图表用于查看流量与故障趋势。排障时打开投递记录，再查看事件详情中的 HTTP 状态、错误码和完整尝试时间线；当前事件状态可能在图表所选时段之后发生变化。所有统计查询仍经过 owner 鉴权，返回 `no-store`，不输出邮件、凭据或响应正文。
