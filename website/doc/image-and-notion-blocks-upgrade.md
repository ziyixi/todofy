# 文章图片与 Notion 内容块扩展：实施和发布计划

日期：2026-09-22。用户本次明确要求规划、修改并上线；本文记录这次增量的范围和验收标准。既有首页版式、头像尺寸和内容发布模型保持现状。

## 现状与目标

- 正文图片目前只能以文章栏宽阅读。本地 Notion 快照有 2 篇文章、20 个图片块，其中截图原图宽度可达约 3000px，图中细字难以看清。
- Notion 转换器支持基础正文、代码、公式、图片、表格、toggle 等，但遇到其他块会停止同步。继续保留这一完整性约束；不能为“兼容”而静默删除作者写的内容。
- 目标是让每张正文图片可点击放大，并扩展排版及媒体内容块，同时保留简洁的学术文章排版。

## 修改范围

1. **图片阅读**：正文中的图片保留原有尺寸、排版和 caption，使用 `photoswipe@5.4.4` 与 `react-photoswipe-gallery@4.1.2` 实现从原位置自然放大。放大时读取已固化的本站 `/media/` 原图；点击或点按图片外侧、按 Esc，或使用一个低调的关闭按钮即可退出。宽幅截图可再次点击、双击或双击点按放大，并支持双指缩放与拖动查看细节。不显示边框对话框、尺寸切换工具栏、画廊箭头或计数器。覆盖层和关闭按钮沿用本站的浅色配色变量，保留有意义的无障碍名称、键盘焦点恢复及系统减少动态效果设置。按图片元数据预留手机端点击区域尺寸，避免离屏延迟加载图片收缩为零。
2. **排版结构**：增加待办事项的静态勾选状态、响应式分栏、可折叠标题、Link Preview 的安全链接展示。Notion 目录块作为放置标记，使用已有文章标题目录数据并抑制页首重复目录；旧文章仍保留原有自动目录。
3. **媒体块**：支持文件、PDF、音频和视频。Notion 托管文件在构建前经过受限下载、过期链接刷新、MIME/大小/来源验证后以本站内容寻址资源提供；音视频使用浏览器原生控件，PDF 和文件提供明确打开或下载入口。外部媒体使用经过校验的链接；仅对明确允许的视频提供受限嵌入，其他 Embed 提供原始链接而不执行任意第三方 iframe。
4. **内容边界**：扩展快照 schema、链接与媒体引用校验、转换测试和文章渲染测试。未知或 API 只给出 `unsupported.block_type` 的组件继续中止发布并报告类型。不得把 Notion 的短效签名 URL、token 或原始私有页面链接写到公开快照。

其他 Notion 块继续由经过校验的本地快照渲染为语义化 HTML，例如 `details`、表格、列表及浏览器原生音视频控件，并使用本站的正文、标题和链接样式。现有 Notion 数据读取已经使用官方 `@notionhq/client`；不引入通用 Notion 页面渲染器或另一套 UI 组件样式，以保留本站排版及公开内容校验边界。

## 验收与发布

1. 运行格式、lint、类型和单测；验证新块在嵌套、移动端和键盘操作下的行为。图片需验证点击或点按后从原位放大、点击或点按外侧及 Esc 退出、宽幅截图进一步缩放和拖动、关闭后焦点恢复、弹层无障碍名称，以及减少动态效果时不产生多余动画；检查手机端图片在加载前有可见、可点击的尺寸，并确认未知块、私有链接和危险媒体仍被拒绝。
2. 用本地真实 Notion 内容重新同步和构建，检查现有中英文文章、20 张图片、目录、媒体清单和截图放大；确认页面其他块样式没有因图片组件及其库样式而改变。新增块目前没有真实内容样本时，明确依靠测试样本验证其行为，不能宣称真实文章已覆盖它们。
3. 以普通提交推送 `main`，运行现有手动 `Production release` 的 `release` 模式。工作流从 Notion 准备正式快照、运行检查、构建并测试候选部署，随后提升同一部署；发布记录与失败门禁继续生效。
4. 发布成功后核对正式域名 `/build-info.json` 的代码/内容身份、文章及图片可用性，并实测图片放大。若任一步失败，先诊断具体阶段和线上身份，再按现有 recovery 流程处理，不盲目重复触发。

这个范围不承诺 Notion 所有 UI 小组件可被 API 等价读取。子数据库、任意子页面、同步块、表单/按钮和非受信任嵌入需要单独设计公开权限、递归与交互语义；在此之前会明确报错，防止线上正文残缺。Notion 的 [Block API](https://developers.notion.com/reference/block) 明确指出部分 UI 块只返回 `unsupported.block_type`。
